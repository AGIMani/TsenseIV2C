压缩包 SHA-256：`266f0971a8451a2c274bbe6c74ad28a088d23d85d29a320a802eaba580416d6f`。

## 已接入的变化

- 原样导入 40 个上游源码文件，排除预编译 dist 与上游 .gitignore，保留原 CAD。
  `vendor/a3-cpp-sdk/sdk-source.json` 记录逐文件哈希；Linux 共享库重新本机编译，
  `src/a32_driver/source_snapshot.json` 记录共享库、硬件配置、曲线源码哈希。
- 复用 SDK 1.1.11 的归零字段判型修正：OpenSpin 同时要求首字节 1..4 与末字节
  0..4。正常电角度浮点的首字节偶然为 1..4 不再单独触发 255。仍保留 SDK
  其余分类规则，例如浮点 2.0 的四字节会判 WAIT；不自行推定固件机械归零状态。
- SDK 1.1.12 的标定闭环替代旧逐关节缩放：大/中/小三种电机各共用一条曲线。
  大号为四指 MCP 19.63 mm，中号为食指/中指/无名指 PIP 与拇指 MCP 16.95 mm，
  小号为 DIP、拇指 PIP、小指 PIP 12.44 mm。SELF 17 上限改为 16.95 mm。
- Python 前向直接计算同一闭环方程，反馈采用解析逆解；与 C++ SDK LUT/float32
  对照，每种曲线 10,001 点，前向最大差约 1.42e-6 mm，逆向约 3.82e-6 度。
  反馈边界容差与 SDK 一致：1e-5 mm、1e-6 rad。命令仍使用 0.005–89.995 度
  防端点限制，网页屈曲范围仍为 0.005–1.565 rad。
- SDK 1.1.13/14 的 SELF 实测/参考电流为安培：直线原始码值 ×0.001374，旋转
  槽 6/7/14/15 的已减零点码值 ÷819。转换仅在 SDK 解析层发生；归零仍为 counts。
- 新遥测/日志采用 `a32-native-sdk-state/v2`，逐电机 `current_unit=A`。
  浏览器和服务端日志头用 `per_sample`，按事件/电机单位解释。旧 v1 或无单位
  标记的 SELF 保留原值。查看器区分 A 与原值曲线；CSV 保留 `_native` 列并新增
  `_a` 与 `current_unit`，不改写旧日志。A3.0/V2 保留各自单位。
- 旋转反馈展示继续按模型范围夹紧，避免严格 SDK 逆解把显示范围错误缩到命令
  限位；起步、控制和 SDK 逆解的严格检查保持有效。

## 保留的项目行为

两款 A3.2 共用更新后的映射、原生库和记录代码；两路 MIT 仍为 50:1。
模型 CAD、拇指零姿态、通道方向/偏移、侧摆 ±0.34 rad 命令范围不变。
连接不自动使能或运动；开启控制仍要求当前连接的有效反馈。软件停止、断开、
取消归零不发送失能，也不保证已被固件接受的运动立即停止。
本次没有引入厂商示例进程、Web bridge、Qt 或跨平台转发；track/play 环境分离。

同一旧动作角度现在按新曲线产生行程；动作文件本身不修改。
已运行的 track/play 进程仍持有旧模块/共享库，停止控制后需分别重启服务并重新
建立页面会话。本次未重启用户正在使用的服务，也未连接或驱动实物。

## 原厂家确认清单的更新

下表区分本包中的明确说明与仍需针对当前实物确认的内容；SDK 注释不能替代
当前固件/机械版本匹配的确认。

| 原问题 | 新 SDK 已提供的信息 | 仍需确认 |
| --- | --- | --- |
| 状态编码 / 255 | `Types.h` 明确没有独立类型位；开环要求 byte0=1..4 且 byte3=0..4，普通 float 低字节可以为 01..04。 | 编码仍有重叠；除注释承认的 float 0=WAIT，代码对低三字节全零、末字节不在 0..4 的值也返回 WAIT（如 2.0）。需明确固件允许的电角度编码域。 |
| DONE / THETA | `A3HandApi.h` 明确直线 THETA 在机械归零锁定零点、开启位置环后发送；旋转保留 DONE。`waitHomeDone` 在发起本次归零后先等待新的 SEEK/RELEASE，再接受 DONE/THETA；旧缓存不能完成新归零。 | 当前固件是否符合此约定，以及全部异常/瞬态分类。不能仅凭任意一个缓存的 THETA 开放控制。 |
| 厂商 estop / reset | 厂商 `estop()` 停止 0x20 流并广播失能。注释说明旋转在 SEEK 时回 WAIT；直线仅设置 DRVOFF，归零状态机仍可能运行至 DONE，再次归零前调用 reset。 | reset 是否运动、改零点或清除标定，以及当前固件的准确行为。本项目原有软件停止不调用该厂商失能实现。 |
| 停止确认 | 注释说明链路在线时继续发 0x02，没有独立 disabled 位；发送失能成功不等于停稳，也不是归零复位。 | 停稳/失能的可靠确认和最大响应时间；残留 SEEK/RELEASE 不能单独证明仍在运动。 |
| 归零参数 | 当前示例为使能后等 200 ms、80 counts，逐槽等待完成、每槽超时 15 s；已不是只间隔 30 ms 发下一路。 | 这些是示例值，尤其 80 注释为典型直线值，不能视为当前全部 18 路的厂家额定参数。 |
| MIT 零点 / 减速比 | 两路输出轴换算均配置 50:1；MIT 电流为 A，状态帧没有 MIT 温度。 | 上电绝对/相对位置、设零与掉电保存规则，及两路当前实物减速比。 |
| SELF 电流 | 直线 ×0.001374 A；旋转已减零点码值 ÷819 A；有符号，零表示无电流。SDK 已换算，网页不可重复换算。 | 有效量程、饱和/无效编码以及连续/短时允许电流。归零电流仍为 counts。 |
| 温度 / 保护 | SELF 为驱动 MCU 温度，原值 /100；SDK 还暴露 0x06 过温/过流事件，事件超时 5 s 失活。 | 事件失活不是故障解除确认；仍需各类驱动的保护阈值、动作与恢复规则。MIT 温度缺失不阻止归零调试。 |

对应依据见 `vendor/a3-cpp-sdk/include/a3/Types.h`、
`include/a3/A3HandApi.h`、`src/A3HandApi.cpp` 和 `examples/enable_and_hold.cpp`。
