# 全链路数据记录与查看

原生 Ubuntu 网页工作台开启角度记录后，浏览器 Worker 将日志保存在访问者电脑的 IndexedDB，每段最多 512 MiB。点击“选择日志根目录”授权本机目录，结束会话后按 A30、A32、V2 保存；未授权或写入失败时仍可从浏览器下载恢复。A3.2 本机 SDK 服务另有服务端日志。启动方式见 `README-UBUNTU.txt`。

用浏览器打开工作台的 `/data-viewer` 或 `tools/hand_control_log_viewer.html` 导入日志。文件在本机解析，旧日志继续兼容；旧记录里缺失的阶段不会被推测补出。

## 关节角阶段（2026-10-09）

关节角对比只保留以下五类，单位均为 rad：

| stage | 含义 |
| --- | --- |
| `retarget` | MediaPipe 等输入经 Retarget 转出的原始机器人关节角；即使后续控制拒绝也保留有效求解结果 |
| `direct` | 直控分支的关节角；V2 为自适应滤波后、采样碰撞处理前的输出；未执行直控时不产生 |
| `ruckig` | 实际 Ruckig 求解输出，保留采样碰撞处理及重新规划之前的结果；直控不产生 |
| `mink` | 实际经过 Mink 后的关节角；关闭 Mink 或只启用碰撞停止时不产生 |
| `sdk` | 主机成功下发的关节角，以实际应用/编码的姿态为准；预览、状态轮询和写入失败不产生 |

统一角度事件为 `type: "joint_angles"`，包含 `stage`、`joints`、时间和帧号等关联信息，SDK 事件必须具有 `sent: true`。重复轮询同一规划 tick 不新增角度样本；A3.2 批量回传使用真实写入时间，避免把整批角度挤在轮询时刻。浏览器只记录收到的规划/成功写入样本，并不宣称覆盖服务器的每一个规划 tick。

只精简重复关节角阶段。电流、温度、角度转行程/旋转位置的中间量、原始骨架、原始报文、发送状态、碰撞与时序诊断继续采集，原有辅助面板及电机 CSV 保留。查看器另可按勾选阶段和关节导出关节角 CSV；未经过的阶段显示暂无数据。

## 使用过程记录

查看器新增“使用过程记录”，按 **型号＋左右手＋设备名称** 汇总，显示开始时间、结束时间、单次时长与各手总时长。从本地手势服务的 `https://127.0.0.1:8766/data-viewer` 打开时，页面按当前型号自动扫描所配置父目录下的 `A30`、`A32` 或 `V2` 子目录，读取每份全链路日志的会话开头和结尾并汇总；切换型号会更新日志列表、使用记录和累计时长，点击“刷新文件夹”可再次扫描。下拉框可选择一份当前型号的日志读取完整曲线。“确认父目录”仅在本机服务的同源页面可用。直接打开独立 HTML 文件时，浏览器无法仅凭文本路径访问本机磁盘，仍需手动选择文件。也可以手动填写时间新增记录、修改设备名称；诊断抽样日志不自动累计。

重复导入同一会话不会重复计时，各分段通过会话标识合并，补齐分段后使用完整会话区间。未正常封存或缺失分段时只累计已记录的时间范围，并显示提示；同一手的重叠区间合并计时。这里统计记录会话时段，包含识别预览、暂停等时间，不等同电机使能时间。缺少型号或绝对开始时间的旧日志需要手动登记。

使用记录和模块折叠状态保存在当前浏览器、当前页面来源下，刷新后保留；可“备份使用记录”导出 JSON 并在其他电脑恢复。清除浏览器数据前请备份。多个文件导入后，使用记录累计全部文件，曲线显示最后一个文件；查看其他文件时重新选择即可。所有主要模块均可点击标题折叠，展开图表时重新计算画布尺寸。

网页逐关节电源开关：会话 `metadata.joint_enabled` 保存初始选择，`metadata.joint_enable_mode="motor_power"` 标识新版断电逻辑。`joint_enable` 记录选择变化，`joint_power` 记录实际电源指令的关节、bus/motor、enabled 和 USB 写入结果；原始报文及 CRC 保存在 `usb_tx`。`conversion`、`h7`、`downlink` 和位置帧的 `usb_tx` 附带 `joint_enabled`，位置目标不再清零。使能选择、USB 指令发送成功与电机实际通电状态是不同概念；当前协议没有电源 ACK，不能把位置目标或 `sent:true` 当成驱动执行确认。A3.0 外接两路没有电源指令，禁止伪造断电事件。旧日志 `disabled_joint_slot_value:0` 仍表示旧版“槽位清零”，查看时按元数据区别。

## 记录位置

| 事件 | 数据与产生位置 |
| --- | --- |
| `mediapipe_raw` | 每次完成的 MediaPipe 检测，包括无手帧；保存所有检测手的原始归一化坐标、world 坐标、左右手分类/置信度及推理耗时。发生在深度融合、坐标变换之前。 |
| `mediapipe` | 实际进入 retarget 的 21 点及深度/输入来源，保留原有事件名。也可以来自项目中共用此入口的其他跟踪源。 |
| `retarget` / `retarget_skipped` | 求解耗时、接受状态或跳过原因；关节角保存在 `joint_angles/retarget`。 |
| `control_target` | 碰撞处理与时序诊断，不再重复保存控制目标角度。 |
| `h7` | 控制 tick 的限幅、故障、时序及发送状态；Ruckig 与成功下发角度分别存入 `joint_angles`。 |
| `conversion` | `UsbController.send_joint_angles` 实际调用角度→行程转换所得的 14 个直线行程、7 个旋转位置以及输入 HW 角度。复用此次转换结果，不为记录再次求逆解。 |
| `downlink` | `send_hand_positions` 的整手位置发送结果。保存从实际 float32 报文解出的数值、8 位线帧序号、来源、完整十六进制报文及 `sent`。直接行程下发没有角度转换事件。 |
| `usb_tx` | `UsbController` 公共写入口的原始报文与写入结果，包括位置、参数、找零等命令。 |
| `telemetry` | 串口收到的每一个长度合法、CRC 有效的遥测包，在 UI 的“只保留最新帧”缓存之前记录。重复/旧帧仍保存，并用 `accepted=false` 标注。 |

以上覆盖主工程共用 `UsbController` 和 `SkeletonWorker` 的链路。`online_control/online_motion_track/pipeline_v2` 自带独立的会话记录机制；独立运行的 CLI `SerialController` 不由主窗口复选框启动记录。损坏 CRC、错误长度的字节不会作为有效遥测入库。

## 时间和关联

每条事件包含会话递增 `seq` 和相对时间 `t`（秒）。服务端使用单调时钟；浏览器的 `joint_angles`、`h7` 和 `downlink` 在存在 `written_at` / `sent_at_unix_ms` 时共同使用原始写入时间换算，避免把一批控制样本压到浏览器接收时刻。批量写入事件的 `t` 可能早于之前收到的其他事件。旧版浏览器 A3.2 日志的电机下发曲线由查看器按已保存的实际写入时间还原并排序；优先沿用 SDK 关节角的时间原点，原接收时间保留为 `recorded_t`，原文件不变。识别、retarget、控制目标和手势下发通过 `frame_id` 关联；多次 Ruckig tick 可以共用同一个识别帧。`timestamp_ms` 是跟踪器交给识别器的时间戳，与 H7 的 `tick_ms` 属于不同的时钟，不能直接相减。

`downlink.command_id` 对应 `conversion.seq`；`wire_seq` 是整手下行协议的 8 位序号。回传的 `telemetry_seq` 是上行独立的 16 位序号，`tick_ms` 是设备时钟，二者不充当命令应答编号。

`telemetry.latest_host_command` 保存记录此回传包之前最近一条成功记录的整手下发事件引用（按手侧区分）。这是主机时间顺序关联，**不是下位机逐条确认**。下发失败不会替换这个引用。`sent=true` 表示完整报文成功写入串口，不保证电机已经执行。

## 回传字段

### A3.2 SDK 1.1.15 电流（2026-10-12）

A3.2 新遥测为 `a32-native-sdk-state/v2`，SELF 实测/参考电流和 MIT 电流均为 A。
SDK 已完成线性 SELF `counts × 0.001374`、旋转 SELF `counts / 819` 换算；
网页和记录层只保留结果，不再换算。归零输入仍为 counts。每路 `current_unit`
以及事件 `telemetry_units` 标明实际单位，浏览器会话头的电流单位为 `per_sample`。

旧 v1 或没有单位标记的 A3.2 SELF 日志仍显示 SDK 原值；旧 MIT 电流仍为 A。
查看器不依据型号给旧数值补上 A。混合日志中的 A 与原值采用分开的曲线；
电机 CSV 保留旧 `_native` 列，安培值写入新增 `_a` 列，并附 `current_unit`。
旧日志不被重写。下面的原值说明适用于原协议及未声明安培单位的历史记录。

### 原协议与历史记录

解析布局参考 `deprecated/main_app_v3.py`，使用主工程 `src/usb/telemetry.py` 解析器，兼容当前 780B 和旧版 932B 帧。

| 电机 | 字段 | 单位/含义 |
| --- | --- | --- |
| 直线 | `pos_ref_mm`, `pos_act_mm`, `pos_err_mm` | 回传目标、实际及目标减实际，mm |
| 直线 | `iq_meas`, `iq_ref`, `grav_iq` | 实测、目标、重力补偿电流，保留协议原值；参考程序未标定成 A，因此查看器不擅自换算 |
| 直线 | `mcu_temp_centi`, `mcu_temp_c` | 原始百分之一摄氏度及 °C；沿用参考程序的温度有效性判定，无效/未上报为 null |
| 直线 | `can_rx_error_cnt`, `can_tx_error_cnt`, `status_b_u32`, `mech_home_state` 等 | 原始诊断和回零状态一并保留 |
| 旋转 | `pos_ref_mm`, `pos_actual_mm`, `pos_err_mm` | 沿用历史字段名，实际是旋转位置 deg，查看器按 deg 展示 |
| 旋转 | `iq`, `iq_ref`, `id_`, `id_ref` 等 | 保留原始电流及其他槽位字段 |
| 旋转 | 温度 | 当前协议没有该字段，显示“没有有效温度回传” |
| 主板 | `board` | 手型、设备时间、IMU 角度、有效标志及诊断计数 |

每条回传保留 `payload_hex` 以便重新解析。非有限浮点数编码为 JSON `null`，不会以 0 冒充有效数据。会话 metadata 中包含本次使用的电机槽位映射。

旧日志若出现 `-2147483.648 mm`，可能是旧解码器把 float32 负零 `00 00 00 80` 当成 int32 后乘以 0.001。主工程解码器已修复此问题。查看器仅在 780B 原始报文相应位置确为负零、且保存值匹配此已知错误时修正位置并重新计算误差；显示修正数量，在 `decode_corrections` 中保留原值和原因，CSV 采用修正值。原日志不被改写；没有原始字节证据的异常值不会被自动清零。

## 图表操作

- 关节角图只展示 Retarget、数据直出、Ruckig、Mink、SDK 下发五阶段；关键点图及电机辅助图保留。
- 选择左右手和任一 L00–L13 / R00–R06 电机，对比转换、成功/失败下发、回传目标与实际位置；查看电流和温度。
- 电机位置、电流、温度和控制周期图的图例均可勾选显示曲线，选择保存在当前浏览器。隐藏曲线不参与十字轴和纵轴范围计算，不影响原始记录及电机 CSV 导出。
- 所有图表支持时间轴联动、滚轮缩放、拖拽和精确值十字轴。绘制降采样保留峰值，日志和 CSV 不降采样。
- 默认开启“纵轴跟随当前时间范围”：横轴缩放或平移时，每张联动图分别按其可见曲线的 `[最小值, 最大值]` 更新纵轴，区间外峰值不会撑大范围；边界按绘制的折线插值计算。常量曲线仅扩展极小的绘制范围，范围文字仍显示相同的最小值和最大值。手动操作纵轴后暂时使用手动范围，下次横轴操作恢复自动适配；也可取消顶部开关。
- “逐帧数据”按所选时间显示最近下发/回传，优先按命令 ID、识别帧 ID 展开上游数据；“导出所选电机 CSV”导出该手侧和电机的全部转换、下发、回传记录。

## 记录完整性

实时线程只入有界队列；回传完整解析、JSON 序列化和写盘由独立线程处理。队列容量 32768，平时约每 0.5 秒或累计 256 条刷新。异常过载时生产线程不阻塞控制，而是在结束事件中报告 `dropped_events`，查看器显示丢弃数。缺少结束标记的文件会提示未正常封存。磁盘写入错误在停止记录时提示，不会报告完整保存成功。

验证命令（使用装有项目依赖的 Python 环境，并给 pytest 指定可写且尚不存在的临时目录）：

```text
python -m pytest tests/test_control_chain_recording.py tests/test_control_session_recorder.py tests/test_recording_serial_lifecycle.py tests/test_usb_v3_protocol_sync.py -q --basetemp <new-temp-dir>
node tests/test_control_log_viewer.cjs
```

测试通过虚拟串口验证数据，没有驱动真实硬件；浏览器外观仍需实际打开 HTML 检查。


## 手势控制的关节角度补偿

网页手势控制的 V2、A3.0、A3.0 with ID、A3.2、A3.2 with ID，左右手均在重定向后对目标角应用以下系数：食指 MCP ×1.2、食指 DIP ×1.2、小拇指 DIP ×0.8、其余四指 MCP ×1.1、食指 PIP ×1.1，再按模型关节范围限幅，随后进入已有碰撞检查、Ruckig 和机构转换。直接模式也应用一次该补偿，并保留其原有的限位规则。系数位于 `online_control/online_motion_track/command_compensation.py` 中的各关节 `*_GAIN` 常量。

`retarget_joint_angles_rad` 和优化骨架保留原始求解结果；控制目标及实际下发记录反映补偿后经过保护与规划的角度。反馈、起步姿态和 motion_play 动作播放不应用此手势补偿。
