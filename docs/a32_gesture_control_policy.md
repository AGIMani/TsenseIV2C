# A3.2 手势下发条件（2026-10-03）

适用于手势页面的 `TsenseI_v3_2` 和 `TsenseI_v3_2_withid`，包括 MediaPipe、WebXR 和 Wuji 输入。开启、丢手、碰撞保持和关节限位恢复按当前 A3.0 手势逻辑处理。动作编辑平台 `motion_play` 的条件没有随本次修改调整。

## 可以开启的条件

1. 本机原生驱动可用（Windows DLL 或 Linux `.so`），选择已标定的左手，当前页面已连接设备且拥有控制权。
2. 已点击“开始识别”。`off`（关闭保护）和 `monitor`（只监测）允许手动开启下发；选择“碰撞停止”或 Mink 时，采样碰撞检查必须可用。
3. 本次连接至少收到过一包有效手部遥测。使用 SDK 手遥测回调时间判断；其他接收包计数不能代替手部遥测。
4. 未正在找零，没有在线 MIT 电机报告故障；反馈手侧应与模型一致。
5. 启用保护时，起步姿态通过碰撞检查，Mink 模式还需满足起步间距约束；`off/monitor` 不要求此检查。

无需保持手可见，无需 20 路反馈齐全、新鲜，也无需先完成找零。起步逐关节采用有效反馈，缺失部分使用上次成功命令或初始姿态。开启时同步重置规划器、求解器和已启用的目标碰撞状态，从该姿态保持，收到下一帧有效手势后跟随。

`off/monitor` 下发时界面明确显示“碰撞保护关闭”，仍执行关节范围与所选运动限制。改变下拉选项不会自动使能或发送硬件命令。A3.0 两款型号也采用此规则，V2 的下发条件保持不变。

## 哪些情况继续下发

| 情况 | 行为 |
| --- | --- |
| 暂时无手、只看见另一侧手、超过 400 ms 没有新目标 | 沿经过检查的轨迹完成最后目标；保留速度、加速度和碰撞保持状态 |
| 已收到首包，后续反馈过期或部分电机缺失 | 继续下发；缺失反馈不当作真实零位置 |
| 控制线程一次采样超过 100 ms | 不因该间隔单独停发；规划最多前进 4 ms，不补发积压帧 |
| 启用保护后某手指运动发生碰撞 | 优先保持相关手指，其余手指继续；目标或邻指位置改变后重新检查能否恢复 |
| 轨迹制动段可能超关节范围 | 先对相关关节重规划，必要时保持该关节；只有无法生成安全结果才停发 |

碰撞和限位恢复共用 `safe_trajectory.py`，手指分组规划共用 `a30/grouped_ruckig.py`。

## 哪些情况仍会阻止或停止下发

- 未连接、SDK 写入失败、连接丢失，或未拥有当前设备控制权。
- 在线 MIT 电机明确报告故障，或遥测手侧不匹配。
- 正在找零。主动找零的反馈检查、失败和 30 秒超时保护仍由 A3.2 驱动执行。
- 输入/求解异常、存在手但目标被求解流程拒绝、非有限数值、无效采样间隔（零、负数、NaN、Inf）。过期输入帧会被丢弃，不作为新目标。
- 经过重规划仍无法满足关节限位、已启用的碰撞保护，或 Ruckig 失败。
- 网页控制心跳超过 2 秒未更新；会话超过 3 秒无人访问时还会被回收、释放设备。
- 用户关闭下发、急停、开始/复位找零、停止识别、切换模型、隐藏页面或退出页面。

故障停止后需手动重新开启；新的手势不会自行使能电机。按钮旁显示禁用原因。

## 保留的 A3.2 差异

### 直控模式

A3.0/A3.2（均含 with-ID）可在手势页选择“直控模式”。选择后碰撞选项固定为 off，重定向角度经硬件关节限位、机构和槽位转换后下发，不经过 Ruckig、额外关节滤波或任何目标/采样碰撞矫正。位置有限值检查、关节和执行器范围、连接、手动使能、故障与页面心跳检查仍生效；速度、加速度和 jerk 上限在直控下不参与规划。

页面切换模式会结束当前识别和设备控制会话；需手动重新开始识别、连接及开启下发。取消直控恢复 Ruckig，碰撞模式可重新选择。模式切换不自动使能。A3.2 仍以 2 ms 为目标采样周期，写入成功后才更新已发送姿态；其右手硬件标定限制保持不变。

A3.0 通过浏览器串口发送，流中断后有最长 2 秒的重建过程。A3.2 在 Python 内直接调用 SDK，因此使用 2 秒网页心跳保护；两者的传输计时机制不同。按本次要求，A3.2 不再因单次采样超过 100 ms 停发。

A3.2 保留自己的硬件映射和关节范围，实时控制目标采样率为 500 Hz。2026-10-03 起，启用 Ruckig 时各型号、左右手和关节类型的规划默认上限统一为速度 10 rad/s、加速度 80 rad/s²、jerk 200 rad/s³，见 [共用运动参数](motion_limits.md)。右手实物控制仍需硬件标定。此次参数修改不需要重新构建原生 DLL 或固件。

## 生效与验证

停止当前下发后，重启本地手势服务并刷新页面，重新连接并开启识别。已运行的 Python 进程不会自动加载改动。

软件回归覆盖无手开启、首包门槛、反馈过期、丢手完成目标、碰撞局部保持及恢复、限位重规划、采样延迟、心跳/故障停止、求解与状态轮询并行、两款 A3.2 的真实碰撞模型和 A3.0 原有回归。使用模拟设备验证 SDK 调用，未执行实体电机运动测试。
