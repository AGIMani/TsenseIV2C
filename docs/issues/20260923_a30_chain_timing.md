## 首包总时间的关联方法

1. `processFrame()` 在 `createImageBitmap(video)` 之前记录 `timestamp_ms`。
2. `control_target.pipeline_timing.capture_to_response_ms` 使用同一浏览器 performance 时钟；用 `control_target.t - capture_to_response_ms / 1000` 重建该图像相对录制起点的时刻。
3. 对每个 frame_id，只取第一条 `sent=true && source=shared_binary_stream` 的 downlink；用其紧邻前方成功 `usb_tx.t` 作为 writer.write 完成时刻。
4. 两者相减得到上述端到端统计。既不采用全部后续保持包，也不将 `sent=false` 的预览 h7 当成真实下发。

精度限制：日志函数本身有少量开销；服务器包头的 frame_id 是最新接收目标编号，wire 是最近完成的控制采样，极短时间窗内编号可能先于新采样一个控制周期。因此该指标是首条“关联指令”到主机 USB 写入完成的近似时间，不能声称是新目标第一次产生非零关节位移的精确时刻。
