## 当前实际换算

| 关节后缀 | 槽位 | A3.0 播放 / 跟踪 | A3.2 播放 / 跟踪 |
|---|---|---|---|
| `thumb_rotaback_joint2` | 第一台，索引 0 | 电机端 = 输出轴 ×50；反馈 ÷50 | SDK 输入输出轴角度，SDK 内部 ×50；反馈 ÷50 |
| `thumb_rota_block_joint` | 第二台，索引 1 | 电机端 = 输出轴 ×30；反馈 ÷30 | SDK 输入输出轴角度，SDK 内部 ×50；反馈 ÷50 |

两关节均先将 URDF 的 rad 转成输出轴 deg。两个型号的普通模型与 with-ID 模型分别使用同一套换算。

A3.0 的 `mit_pos_deg[0:2]` 是电机端角度。A3.2 的 `sdk_targets.mit_pos` 是 SDK 接口的输出轴角度，不能直接比较这两个字段的数值。

例如两个关节均为 30°：A3.0 线上的两个 float 为 1500°、900°；A3.2 传给 SDK 的是 30°、30°，最终线上的两个 float 为 1500°、1500°。

A3.2 播放页面的遥测列表使用零起始编号：`MIT 0` 是 rotaback，`MIT 1` 是 rota_block。A3.0 文档中的 M1 是 rotaback，M2 是 rota_block。单说 “MIT1” 存在编号歧义，应同时核对关节名和数组索引。

## 判断与后续定位依据

当前仓库中，同一型号、同一关节姿态的播放和跟踪没有减速比差异，没有发现跟踪额外乘一次比例。A3.0 与 A3.2 第二路的 30 / 50 差异是现有两条路径的配置差异；用户已确认播放正确，本次不将它擅自统一。

若播放在相同姿态下实物正确、跟踪偏大，需继续比较跟踪产生的关节目标、碰撞 / 轨迹处理后的角度与播放基准，而不是直接减小下发减速比。要确认机械比例，还需同一零位、另一拇指自由度固定时的两个实测相对角度。现有信息不足以认定具体是手势标定、零位或机械比值错误。
