# A3.0 按手指同步与显示/下发样本对齐

日期：2026-09-23。仅修改本地源码；没有更新 node0，没有驱动真机。

## 最终行为

- 原来整手 20 轴一起完成；现在拇指、食指、中指、无名指、小指各 4 轴组成 5 组。每组内部 Ruckig 时间同步，组间独立，所有组使用同一 2 ms 采样时钟。
- 拇指两路根部旋转和两路弯曲同组；其余每指的 MCP/PIP/DIP 与侧摆同组。这样保持每根手指中间运动路径的协调，同时避免其他手指拖慢它。
- 输出合并后仍经过完整手部的碰撞检查和全轨迹位置极值检查。碰撞仍保持相关手指，手势变化后重试。重试没有提交的候选不会推进其他组第二次。
- 预览使用只含关节样本的二进制流，不包含 USB 报文；在屏幕绘制前读取最新样本，不再等待下一次识别响应才显示 Ruckig 运动。
- 开启实时下发后，模型只使用最后成功完成 USB 写入的样本。写入失败、仍在等待写入、过期响应和旧 epoch 都不能发布新的模型姿态。HTTP 状态/识别响应不覆盖这个姿态。
- 新增 `motion_synchronization` 和 `model_sample` 记录，后者包含 epoch、tick、frame_id 及写入完成到绘制前回调的时间。它不是电机到位确认或屏幕实际发光时间。
- 参数仍由服务器提供给浏览器。本次保留用户工作期间修改后的配置：弯曲 20/400/600，侧摆 1.5/10/80，拇指旋转 4/60/360，单位依次 rad/s、rad/s²、rad/s³。

- 预览流、下发流都在浏览器测试中执行；预览不占用下发租约。新增文件已核对包含在部署包中。

MediaPipe 约 30 Hz、新目标计算时间、当前速度/加速度/jerk 约束、每根手指内部协调和碰撞仍有物理与计算上的响应时间。实现减少了组间不必要等待和显示/下发采样差异，不能将它称为零延迟或已经测得真机同步极限。真机机械同步程度仍需带电机反馈的新日志测量。
