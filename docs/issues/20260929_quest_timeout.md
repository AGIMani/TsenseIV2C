## 修复

1. 上传骨架请求使用剩余 250 ms 新鲜度预算，避免过期姿态占住唯一请求
   达 2 秒并额外退避 500 ms。失败姿态不重发，只取最新待发帧。
   握手仍保留较长超时及重试；终止消息保持独立处理。
2. 电脑轮询遇到网络错误、超时或 HTTP 408/429/5xx 时先上报无手输入，
   保留配对并重试。失效会话等其他 4xx 仍结束识别。
3. Quest XR 或文档暂时失焦时发送追踪丢失、清空待发姿态，保留 XR 会话；
   返回前台后只发送新采样。用户停止、真实 XR end、pagehide 仍结束采集。
4. 页面分别显示等待配对、XR 已结束、失焦暂停、上传过期和所选手不可见。
   新日志记录接收中断/恢复事件，原生骨架附带上传耗时、超时及替换计数。

350 ms 的服务端数据过期阈值、关节范围及硬件下发保护保持原有规则。
电脑页面隐藏时的停止规则也保持原样。更换手型后仍需用新码重新配对。

## 验证

- 21 项 JS 单元测试通过，包括慢上传让位、接收超时恢复、不复用旧帧及状态区分。
- Quest 浏览器模拟测试通过：失焦无姿态上传、恢复不重建 XR、真实结束仍停止。
- 33 项 Python 配对、时效、乱序和 HTTP/TLS 路由测试通过。
- 真实服务加浏览器集成通过：注入 450 ms 轮询延迟后，配对码保持不变且
  自动恢复 retarget；没有相机访问或硬件下发。
- 尚需真实 Quest 在原 Wi-Fi 环境复测。软件恢复测试不能证明无线网络抖动已消除。

生效需要电脑控制页和 Quest 采集页都刷新，然后重新配对并进入 XR。
