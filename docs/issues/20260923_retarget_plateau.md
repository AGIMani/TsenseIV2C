## 结论与证据

检查用户提供的 10 份 JSONL，SHA-256 确认 `143536` 和 `150111` 各有一个重复副本，即 7 份独立控制记录和 1 份采样诊断记录。原始文件保持不变。

截图对应 `hand_control_20260923_145628_307000.jsonl` 的食指 swing。这里有两个叠加的原因：

1. **19.6599–24.3022 s 没有 retarget 新结果。** 前后 frame_id 为 531 和 667，中间 135 个原始识别帧中 134 个没有手、1 个为 Left。恢复识别后输入姿态已改变；旧查看器直接连接缺口两端，画出了并不存在的连续运动。27.3354–29.4812 s 的另一个缺口中有 38 个无手帧、22 个 Right 帧。不能通过继续使用错误手别或补造姿态来消除这些缺口。
2. **24.3 s 之后 retarget 已恢复，H7 仍保持约 -0.160493 rad。** `planner_sample` 显示 `finger_hold`，碰撞对包含拇指 MCP 与食指 DIP；候选样本首次越过接触边界的穿透量约 0.00002–0.00004 mm。该数值很小，因为控制器在接触边界前停住，不能据此认定可以忽略碰撞。旧逻辑将接触对的两根手指同时冻结，连可以安全退让的一根也不能动，造成持续重试与延迟释放。

此外，`143102` 中食指 swing 在 11.104–18.505 s 等时段持续输出约 **0.35 rad**，且期间存在连续 retarget 帧。这是当前模型限位饱和，不是缺帧；本修复没有扩大机械限位。诊断文件按采样保存、包含多次启停，不能把其全部记录间隔解释为识别丢失。

## 修改

- `online_control/online_motion_track/a30/control.py`：遇到接触，先对接触手指逐一尝试“只保持其中一指”的候选，检查从当前已接受姿态到完整候选姿态的路径。只有完全通过原碰撞检查，才让另一指继续运动；否则退回原先的多指保持。选定保持方案后重新生成 Ruckig 样本并检查，不直接发送探测姿态。每次最多五个额外候选，碰撞穿透阈值仍为零，关节与速度/加速度/jerk 检查沿用原链路。
- `static/app.js`：记录 `retarget_skipped`，区分 `no_hand`、`wrong_hand`、`solve_rejected`、`missing_retarget`，保留帧号、手别、时间戳及服务端消息。诊断记录器也采样保存该事件。
- `tools/hand_control_log_viewer.html`：retarget 超过 300 ms 的记录间隔断线显示，先分段再缩放和降采样，悬浮检查不在缺口内部借用远处的角度。详情增加 `planner_sample` 和 `retarget_skipped`；对采样诊断日志明确提示不能据间隔推断丢手。300 ms 是显示缺口阈值，不是新的运动保持阈值。

## 实际数据回放

固定夹具 `tests/fixtures/a30_plateau_145628.json` 保存截图时段的已接受姿态和后续控制目标。使用生产 A3.0 控制器、分指 Ruckig、真实 MuJoCo 碰撞几何及编码，按 500 Hz 回放 3 秒。基线只恢复旧的“两指一起保持”决策，其他代码、输入与初始状态相同。

| 指标 | 旧保持策略 | 修复后 |
|---|---:|---:|
| 食指相对初始姿态移动超过 0.01 rad 的等待 | 670 ms | 160 ms |
| 存在手指保持的采样数 / 1500 | 288 | 60 |
| 已输出样本的几何接触数 | 0 | 0 |
| 单步计算中位数 / P95 | 0.468 / 0.824 ms | 0.463 / 0.795 ms |

回放从日志中的姿态以零速度、零加速度初始化，使用浏览器收到控制目标的时间，**不是原运行轨迹或机械响应的精确重建**。因此 670→160 ms 是同条件离线对比，不代表原日志中数秒平台会按这个比例缩短。丢手期间不能恢复没有采集到的动作。
