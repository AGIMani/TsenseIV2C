# A3.0 边界浮点误差导致跟随锁定：修复与验证

输入日志：`hand_control_20260923_123602_920000.jsonl`。

原问题在固定 2 ms 离线回放的 45.5565 秒、第 1258 帧复现：中指 MCP 输出为 `-1.4140965853708407e-9 rad`。轨迹检查容差为 `1e-7`，转换层为 `1e-10`，因此前者通过、后者抛出 `A32:AngleLimit`，控制进入 `blocked` 并拒绝后续目标。

## 修复

- A3.0 轨迹检查和角度转换共用 `JOINT_LIMIT_EPS_RAD = 1e-7`。超过容差的实际越界仍须重规划或拒绝转换。
- 容差内的边界噪声在碰撞检查之前归一到合法边界；检查、模型角度、后续 Ruckig 输入与报文转换使用同一位置。
- 几何转换产生的 `4e-16` 一类伪下限归一为对应的精确 URDF 端点，避免零位在多个模块中出现不同表示。
- 分组轨迹真正结束、目标速度和加速度均为零时，提交精确目标位置及零导数，避免静止状态的数值残差再次触发零时长重规划错误。运动中的正常导数没有统一清零。
- `planner_sample` 日志增加 `sample_ticks`、`target_ready`、`tracking_transition`、`last_error`、`boundary_roundoffs` 和最后一次边界归一记录，方便区别正常保持、碰撞保持和硬故障。
