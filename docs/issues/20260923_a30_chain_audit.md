# A3.0 手势跟踪链路检查与恢复修复

范围：旧 A3.0、A3.0 with ID；左右手；Stop / Mink；Ruckig / 直接跟随。
检查链路：摄像头帧队列 → 21 点映射 → 目标碰撞处理 → 采样与路径碰撞检查 → 二进制流 → 浏览器校验 → 串口写入 → 模型显示。

## 已修复的问题

1. **邻指退开后，被暂停手指没有恢复。** 原逻辑仅检查该手指自己的目标是否改变；张开目标保持不变时无法释放暂停。现记录其他手指的已接受位置，在邻指移动后重新尝试规划；每个候选仍经过完整的采样路径检查。详见 `20260923_collision_hold_resume.md`。
2. **直接跟随时整手停止，妨碍安全退让。** 组合测试复现 with-ID + Mink 的左右手都可能卡住，目标层显示 clear，但采样层停在旧姿态。现探测整根手指的保持方案，让可安全退开的手指继续运动，并再次检查重组后的完整路径；滤波器只接收最终通过检查的位置。不能确认安全时仍阻止输出。
3. **手势求解与控制器提交之间存在并发空隙。** 另一帧、重建起点、模式切换或关闭会话可能插入这两个阶段之间。A30 会话改为可重入锁，完整覆盖求解和提交，以及这些控制操作；控制采样仍使用独立控制器锁。
4. **重复或迟到帧误触发锁存故障。** 现在单独抛出 `StaleFrameError`，拒绝旧帧且不覆盖新目标、不清空有效输出。非有限时间戳、无效新输入等仍进入故障状态。HTTP 仍返回错误，正常客户端继续采用单请求在途队列。
5. **预览流的初始时钟映射永不更新。** 初次状态响应较慢时，所有后续预览样本都会被永久误判为过期。现每次状态更新都刷新现有流的时钟映射，不额外开启第二条流；旧会话回调不能提交到新流。
6. **带 ID 模型左右手标定不一致。** 左手腕点和部分指尖已有人工修改，右手仍为自动初值。经用户确认，使用现有 `--sync-right-keypoints` 将左手按 XZ 平面镜像到右手；保留左手原文件，并自动备份原右手文件。Draft 状态仍保留，此次同步不代表全部 21 点已完成标定。

## 各层核查结论

| 层 | 核查内容 |
| --- | --- |
| 输入 | 单个在途请求和有限待发帧；旧帧拒绝；停止后忽略迟到回调；21×3 有限坐标校验 |
| 求解 | 原始求解目标、碰撞处理后目标、最终采样姿态分开保存；传输恢复不重置手势估计历史 |
| 碰撞 | with-ID 只检查不同手指之间的 90 对胶囊；手掌/腕座/安装外壳不参与；旧模型保留其碰撞配置 |
| 轨迹 | Ruckig 按手指分组；检查轨迹范围极值和采样路径；直接滤波后也检查路径并反馈已接受姿态 |
| 恢复 | 碰撞保持允许安全重试；异常输入等硬故障不会被普通摄像头帧解除；重建起点和模式切换使旧流失效 |
| 编码 | 共用 A3 编码器；20 关节、108 字节位置帧；线性电机负号只应用一次；旋转传动比和左右手映射一致 |
| 串口 | CRC、会话版本、范围、样本时效和等待后的时效复核；停止取消排队写入；成功写入后才提交显示位置 |
| 显示 | 开启下发时显示成功写入的样本；纯预览显示检查后的样本；预览时钟可随状态刷新恢复 |

## 验证

- Python 相关回归：167 项，包含并发、过期帧、碰撞恢复、模型、映射、范围、编码和直接跟随。
- 浏览器逻辑单元测试：121 项。
- 确定性压力矩阵：16 配置 × 8 次动作/张开循环 × 700 采样 = **89,600 个采样**。固定随机种子 731，每步 3 ms；逐步检查控制状态、模型接触数及 108 字节输出，每次循环检查恢复到初始张开姿态。
- 新增失败用例先在修复前复现，再在修复后通过：事务交错、旧帧误锁存、预览时钟、左右手直接跟随卡住。

## 验证边界与生效

这些测试证明所覆盖情形能够恢复，没有关闭碰撞检查。关节空间直线退让仍可能没有安全路径；此时保持是正常保护，不保证任意目标都可到达。碰撞采用离散路径检查和简化胶囊，不能等同于真实机械结构连续扫掠证明。直接模式的滤波不提供 Ruckig 的速度/加速度/加加速度约束。

本轮没有连接或驱动真实机械手，未验证下位机实际接收频率、机械跟随误差或完整实机标定。未部署 node0，也未重启用户正在使用的服务。Python 修改需要重启本地跟踪服务，网页脚本需要刷新；已创建会话需要重建才能读入新的右手标定。
