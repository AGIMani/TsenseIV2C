## 已确认的实现依据

1. 当前 TopoRetarget 在 `retarget()` 中按每帧 5–17 掌宽将输入映射到机器人尺度；目标函数包含交互网格、骨方向、初始化先验、上一帧先验，没有独立指尖接触项。
2. 本地 AnyDex 的 `vendor/anydexretarget/optimizer/analytical_optimizer.py` 根据人手指尖距离计算 alpha，在目标函数中加入 `w_contact * alpha * ||p_thumb - p_partner||²`。本地配置采用 2/4 cm 阈值和权重 6。其单位、残差及其他权重与 TopoRetarget 不同，不能直接照搬数字。
3. hand 的网页采集端发送 world landmarks；V3.0/V3.2 的 `prepare_points()` 提供三维骨架，具体模型由 profile 选择。应使用当前会话交给求解器的同一帧骨架，而不是截图坐标、画布尺寸或三维视图缩放。

## 1. 用当前骨架尺度计算阈值

对进入 TopoRetarget 的三维骨架 P：

```text
S = ||P[5] - P[17]||        # 当前帧三维掌宽
d = ||P[4] - P[8]||         # 当前帧指尖间距
rho = d / S                # 无量纲捏合比例
T_full = 0.20 * S           # 达到完整捏合权重
T_start = 0.50 * S          # 开始逐步吸合
u = clip((0.50 - rho) / (0.50 - 0.20), 0, 1)
alpha = u*u*(3 - 2*u)       # smoothstep
```

上述 0.20/0.50 是第一版调试起点，不是已经通过实测的最终参数。掌宽 70 mm 时对应 14/35 mm；掌宽 90 mm 时对应 18/45 mm。距离与掌宽同时缩放时 rho 保持不变，避免手大小影响触发。三维距离也避免把二维投影重叠误当成指尖接触；识别器自身的深度误差仍需实测。

第一版使用连续权重，不引入二值吸附状态。先用当前有效帧直接算比例，避免新增滤波延迟；若阈值附近仍有抖动，再基于录制序列评估轻度比例滤波。无效/退化骨架不能触发捏合，沿用现有丢帧处理；切换手侧、模型、停止采集时重置相关诊断状态。

## 2. 在现有优化器中加入指尖闭合残差

复用机器人 FK 的标定关键点，设机器人掌宽为 S_robot：

```text
r_pinch(q) = sqrt(lambda_pinch * alpha) * (FK4(q) - FK8(q)) / S_robot
J_pinch(q) = sqrt(lambda_pinch * alpha) * (J4(q) - J8(q)) / S_robot
```

将三个残差分量加入现有残差向量及解析雅可比。沿用当前最小二乘目标 `0.5 * dot(r, r)`。alpha 由输入计算，每次求解中固定，因此无需对 alpha 求关节导数。有限差分回退、候选初值比较、线搜索、最终损失都必须使用同一新增项。

完整捏合时目标为机器人 4–8 重合，过渡区逐步增大闭合优先级。保留现有骨方向和拓扑目标帮助维持对指姿态。这个项直接作用于拇指和食指；整体拓扑耦合可能间接改变其他手指，需用对照验证，不能声称其他手指绝对不动。

第一版采用软约束，权重扫描例如 5/20/80，以实测闭合误差和姿态选择默认值，不能照搬 AnyDex 的 6。软约束并不数学保证零误差；若仍存在明显缝隙，区分权重竞争、迭代不足、关键点标定、关节限位和可达性后调整。必要时只在强捏合且闭合误差偏大的帧评估有限增加迭代，先测耗时再决定。

关键点 4/8 应对应指腹接触位置。先核对现有 YAML 标定；点重合和实体表面接触不一定等价。碰撞处理后的最终姿态也要单独计算距离，避免仅优化输出闭合但最终显示或执行仍有缝隙。

## 3. 参数、界面和改动位置

- `TopoRetargetConfig`：增加捏合开关、完整捏合比例、开始吸合比例、捏合权重，验证 `0 <= full_ratio < start_ratio`、权重非负。
- `retarget()`：使用当前有效三维帧计算尺度/距离/alpha，形成单帧上下文传入优化器。
- 残差、解析雅可比、`_loss_breakdown()`：加入一致的 4–8 项，复用现有 FK/Jacobian。
- profile 与 `src/utils/retarget_runtime.py` 参数入口：提供会话级控制。关闭时走原算法行为；`use_topo_optimization=False` 时明确提示捏合约束未生效。
- 网页会话/管线需透传诊断数据，目前 `HandModelSession.retarget()` 主要返回关节值，不能只在 solver 内添加后就假定界面可见。
- 窗口显示：输入掌宽、输入 4–8 距离、当前动态阈值、归一化比例、alpha、机器人求解后及最终输出的 4–8 距离。控件优先提供开关、吸合范围和力度。
- 日志保留原始输入及以上诊断，支持同一段录像开/关约束对照。

## 4. 验收安排

1. 关闭功能：同样输入、相同初始状态下与备份算法输出一致。
2. 尺度不变性：骨架整体缩放 0.5/1/2 倍、刚体旋转和平移，rho 与 alpha 一致，阈值按尺度变化。
3. 连续开合：跨越两个阈值无权重跳变，张开后无残留吸合；丢手/换手后不继承错误状态。
4. 几何和优化：新雅可比与有限差分一致；测试左右手、关节限位、退化帧，并与不开约束时的距离及姿态比较。
5. 可达的标定捏合姿态：第一版以稳定后的 4–8 距离 <= 2 mm 作为拟定验收目标，同时检查碰撞处理后的距离；如不可达需报告原因，不能用挪动显示点代替求解结果。
6. 其他手势：张手、握拳、拇指对中指，以及其他三指姿态偏差对照。
7. 实时性：报告同一输入序列的求解耗时中位数/P95及迭代数；闭合精度与响应速度共同决定参数。

实施顺序：核心残差与验证 → 当前模型调参 → 窗口控件和诊断 → 同帧录像对照。第一轮先验证纯求解和可视化效果。
