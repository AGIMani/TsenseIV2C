# 非 V2 碰撞外包络与运行时优化

2026-10-03：覆盖当前注册的 A3.0、A3.0 with-ID、A3.2、A3.2 with-ID，共八份左右手 URDF、174 个原有 collision link。V2、厂商原始导出与历史备份不参与重写。视觉网格、关节、惯性和关键点标定保持原样。

## 几何生成

`tools/generate_profile_collision.py --model all` 同时生成 URDF 碰撞引用、四款型号的 `collision_geometry.yaml` 和八份运行时 MJCF。四个 prepare 脚本接入同一生成流程。使用项目 Python 环境运行；生成需要 NumPy、SciPy、trimesh、PyYAML，运行时不需要载入 CAD 或重新拟合。

1. 按各侧 URDF 的 visual origin、旋转和 scale 将源顶点转换到 link 坐标。
2. 从源凸包的支撑平面构造保守外包络，自适应增加平面，直至最大外扩不超过 0.35 mm。较简单的零件直接保留完整凸包。
3. STL 写入后重新读取，验证源顶点全部位于包络内，并重新计算最大外扩。各型号的 `collision_mesh_report.json` 保存源与输出哈希、顶点数、外扩和覆盖结果；任何失败会终止生成。

外扩相对于**源网格的完整凸包**计算，凹洞仍被填平；这不是对凹面误差的 0.35 mm 承诺。此轮无需增加凸分解块数。每只手仍使用 15 个活动指节网格；普通型号的掌部盒也换成完整掌壳的一个外包络网格，with-ID 保持原有仅跨手指检测范围。同指内部、安装件等原有排除项不变，检测对数仍是普通型号 100 对、with-ID 90 对。

## 查询和路径检查

Mink 保留原有 QP、关节约束、回溯次数与 0.025 rad 基础路径采样步长。每次投影使用精确浮点姿态作为缓存键，复用已计算的运动学、间距和可行性；不进行姿态量化，也不跨帧累积缓存。

运行时从 MuJoCo 编译后的顶点验证包围球及局部盒，再计算球、世界轴盒和旋转盒的分离下界。只有下界足以证明满足安全间距时才跳过窄相查询，其余仍调用 MuJoCo。MuJoCo 3.10 在部分分离网格上返回零距离；对此额外检查见证方向与凸包面法向的完整顶点投影区间，只有确认区间分离才给出正间距，否则继续按不安全处理。NaN/Inf 查询结果不能被接受为安全。

Mink 的 `min_distance_mm`、`raw_min_distance_mm` 和 `closest_pair` 对应保守间距；诊断字段 `distance_kind=conservative_clearance` 明确这一点。这些数值用于安全比较，不应当作精确表面测距。

普通型号拇指尖与其他指尖的原有间距为 0.05 mm，其余为 0.5 mm；with-ID 保持原有全部 0.5 mm。间距按关节部位识别，不再依赖 `_capsule` 文件名。Stop 的穿透容限仍为零，路径采样与二分次数保持原值；只执行运动学与碰撞阶段，不再在每个采样点求解动力学和接触力。

新外壳回归发现原基础采样曾遗漏指尖间约 0.013 mm 的短暂穿透，已保存固定路径用例。Mink 现在对接近接触的采样间隔追加保守位移检查与必要细分；不能确认无穿透的区间不放行。Stop 和硬件下发继续沿用原有的轨迹采样检查，不能将整个控制系统理解为完整的连续碰撞检测。

每次 Mink 投影默认最多追加 128 次细分，可通过构造参数 `max_path_refinements` 调整。预算耗尽时不接受尚未确认的路径，输出保留在已验证安全的姿态；诊断记录预算、使用次数和是否耗尽。这会在少数复杂接触姿态中更保守地保持手势。预算限制的是细分数量，不是硬实时毫秒期限。

## 原手势界面

非 V2 的 `off/monitor` 可手动开启下发。界面标明保护已关闭；连接、遥测故障、控制权、心跳、关节限制与所选运动限制仍有效。开启 Stop/Mink 而相应检查器不可用时继续阻止下发。参见 [A3.2 手势下发条件](a32_gesture_control_policy.md)。

停止下发后重启手势服务并刷新页面，重新创建识别会话以载入新几何。此次修改无需重建固件或 SDK 原生库。

## 性能结果

WSL、Python 3.12.3、MuJoCo 3.10.0；每个型号/手侧 56 个连续目标，优化版和参考版交错运行三轮，各 168 次投影。目标包含张手、弯曲、对捏、交叉、释放及一个记录姿态的往返。只测碰撞投影，不包含 retarget、相机、通信和渲染。

参考版使用相同最终几何、间距、QP、路径检查与分离证书，保留失败早退；关闭重复查询缓存和几何筛选，Stop 使用原完整 mj_forward。下表隔离的是查询优化收益，不能当作相对原胶囊系统的整体收益。
