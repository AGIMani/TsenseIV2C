## 几何与配置

原包右手已按照 XZ 平面反射生成，项目直接使用其数据；左右手仍使用相同标量关节角。
腕部坐标原点已按包内 `base_frame.json` 移动到第1安装孔，安装面为 Z=0；未额外旋转或平移。

21点配置按各侧关节中心及外壳末端重新生成，保持待实机标定状态。URDF 碰撞外包络、MJCF、
初始姿态和关节分组同步更新，继续只启用不同手指之间的碰撞及 Mink 分指运动检查。

`source_mapping.yaml` 保存压缩包哈希、两侧来源成员名、原始关节/惯量属性、名称映射和资源
校验值；`source_package/left`、`source_package/right` 只保存来源配置，不再保存重复 URDF。
离线连杆参考算法只保留必需数值常量，已移除其 `A3.2_source.urdf` 依赖；数值换算结果未变。
track/play 打包列表均已同步，只携带当前左右手的 URDF。

重新导入命令（在项目根目录，参数为来源压缩包的实际位置）：

```bash
.venvs/track/bin/python tools/import_a32_customer_exterior.py /path/to/外壳版.zip
```

父目录的 `model-backups`。脚本不会执行来源包内的启动脚本或安装配置。

更新后分别重启 track/play 服务并刷新网页。两套 Python 环境继续独立，无 Qt 依赖。

## 客户能否取得模型

当前 track 接口输出关节结构和 STL 地址；play 网页直接下载 URDF 和 STL 以便 Three.js 渲染。
客户可以通过浏览器网络工具读取这些响应。隐藏目录、改后缀、压缩或前端加密只能提高提取门槛，
不能保证对运行客户端的人保密。浏览器能力参见 [Chrome Network 文档](https://developer.chrome.com/docs/devtools/network/reference)。

如果需要模型不交付给客户，应把完整模型、求解和渲染放在自己控制的服务器，客户端只收图像/视频；
这需要改造当前架构，并评估网络延迟。若必须离线运行，可交付精简外观模型，把高精度 CAD 和内部
结构留在内部；本机资源封装、权限和授权校验可以减少误拷贝，但不能承诺防逆向。

删除工作目录文件不会移除 Git 历史中的旧模型。本次没有重写远程历史；客户交付应使用 allowlist
部署包，不包含 `.git`、历史导出和项目外备份。参见 [GitHub 删除文件说明](https://docs.github.com/en/repositories/working-with-files/managing-files/deleting-files-in-a-repository)。
