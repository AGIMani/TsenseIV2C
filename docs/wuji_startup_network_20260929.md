# Wuji 启动与采样修复（2026-09-29）

## 启动

在 CMD 执行：

```bat
cd /d D:\Qtworks\hand
start_local_and_update_node0.cmd --local-only
```

每次启动都会读取当前网络，不再将 Windows/node0 的 LAN IP 写死在 CMD 中：

1. 尝试 node0 名称、上次成功记录的地址、这台 node0 已知的地址；通过已有 SSH 主机密钥验证身份。
2. 通过 SSH 读取 Windows 连接地址和 node0 返回 Windows 时使用的实际源地址。node0 的 SSH 别名地址可能与 UDP 源地址不同。
3. 检查手套网口、源地址和子网。左手设备当前配置是 `192.168.1.100:50001`，Windows 手套网口是 `192.168.1.50/24`。它们独立于 WLAN 网段。
4. 更新限定到当前 Windows/node0 地址的 UDP 防火墙规则。若手套源地址在重启后丢失，只在能确定专用静态网口时补回；不会关闭 DHCP 或更改网关。
5. 同步 node0 的 `bridge.env`，地址变化时重启手套采集服务。`--local-only` 仍不部署 node0 的项目代码，但会同步本任务所需的手套网络配置。
6. 关闭本项目原有启动器、手套中继与网页服务，再启动新服务。保留其他项目服务。

换网段后首次运行可能弹出 Windows UAC，需选择“是”才能更新防火墙。规则已匹配时不弹窗。检测或授权失败时保留原有进程，并报告原因。

只检查、不更改服务或网络：

```bat
start_local_and_update_node0.cmd --local-only --check-only
```

如果所有已知地址都不可达，并且 `node0` 名称不能解析，指定一个当前可达地址：

```bat
start_local_and_update_node0.cmd --local-only --wuji-node0-host 192.168.88.229
```

手套使用已知静态 IP；脚本不会通过扫描猜测任意未知手套地址。如果修改过设备静态 IP，使用 `--wuji-glove-host` 和 `--wuji-glove-source` 提供设备地址与对应本机地址。多个专用网口无法唯一识别时会明确报错。

每次启动在 `logs/local-and-node0/<时间>/network.json` 保存检测结果；最近成功配置存于 `.work/wuji-network.json`。node0 修改前的环境文件备份为 `~/wuji-glove-bridge/bridge.before-network-auto.env`。

## 这次采样停发原因

新日志使用 A3.2 withid 模型。原始 SDK 日志有 4 次 `control_dt_s=0.0`。本机 Python 的 `time.monotonic()` 使用 GetTickCount64，分辨率为 15.625 ms，而控制循环期望周期为 5 ms；同一时间刻度内的两次唤醒被误判为零周期。

控制循环改用 QueryPerformanceCounter 对应的 `time.perf_counter()`。调度延迟允许为任意有限正值，规划器仍最多推进一次 5 ms 的轨迹，避免延迟后突然追赶。真实无效数值、失联和碰撞保护继续有效。

日志还有 27 次 Mink 输出距离校验失败。上一轮加速将距离查询上限缩到碰撞间距，在 A3.2 的网格上与最终完整查询不一致。现已恢复相同的 0.05 m 查询范围，保留胶囊几何的保守快速排除。

已经停止的控制器不再因每次无效输入重复发送急停；失败的急停会保留待重试状态。显式急停仍发送命令。记录输入异常时保留原始原因和发生阶段，避免后续急停的 I/O 错误掩盖原始错误。
