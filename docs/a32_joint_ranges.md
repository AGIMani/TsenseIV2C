# A3.2 关节范围与 swing 坐标更新

更新：2026-10-09。适用于 A3.2 裸手、A3.2 with ID 的左右手模型，以及手势跟踪、motion_play。

## 当前范围

| 关节 | 模型/页面范围（rad） | 下发范围（rad） | 初始值（rad） |
| --- | --- | --- | --- |
| 全部 PIP / DIP（包含拇指 PIP） | `[0.005, 1.565]` | 与机构及硬件范围取交集 | `0.005` |
| 全部 MCP（包含拇指 MCP） | `[0.005, 1.565]` | SDK 1.1.9 下为 `[0.005, 1.565]` | `0.005` |
| 食指、中指、无名指、小指 swing | `[-0.35, 0.35]` | `[-0.34, 0.34]` | `0` |

四指 swing 以 `TsenseI_V3.2_hand_withid_fixed/urdf/TsenseI_left.urdf` 和
`TsenseI_right.urdf` 为参考，恢复 with ID 的原始 origin、轴方向和限位。
裸手保留自己的关节位置、网格和连杆尺寸，四指 swing 正方向与参考 ID CAD 对齐，
因此其轴向相对原始裸手 SDK 取反。此前正角度版本的零位偏移被移除，`0` 回到摆动中点。
左右手 MJCF、执行器范围和初始姿态同步更新。

## 模型姿态与 SDK 下发

```text
q_command = clamp(q_model, -0.34, 0.34)  # rad
sdk_self_degrees = degrees(q_command)
```

四指 swing 直接把限幅后的模型角转换为 SDK 的度，不加 `0.35` 偏移、不缩放、不再次取反。
实际命令范围约为 `[-19.480565, 19.480565]°`。
反馈由 SDK deg 直接换回模型 rad。网页 motion_play 允许编辑完整 `[-0.35, 0.35]`，
最终下发采用较窄范围；实时跟踪的轨迹控制器也采用驱动提供的有效范围。

| 关节 | self 槽位（从 0 开始） |
| --- | --- |
| 食指 swing | 15 |
| 中指 swing | 14 |
| 无名指 swing | 7 |
| 小指 swing | 6 |

机构内部仍使用原始裸手 SDK 坐标，四指 swing 的机构输入为 `-q_model`；
这只用于源机构计算，最终 self 命令采用上述直接换算。
拇指零位、MIT 单位/减速比保持原有方式。直线命令自 SDK 1.1.9 更新起按新版机构曲线归一化；反馈采用同一曲线的逆，详见 [SDK 接入](A32_NATIVE_SDK.md)。
四指 DIP 模型保留；新版 SDK 下行程上限统一为 12.44 mm。文末旧行程数值仅记录历史。
本次验证不驱动实体手，命令范围指软件下发值。

## 修改入口

- `src/a32_kinematics/joint_coordinates.py`：范围、中立值、旧/新坐标及旧动作转换的统一定义。
- `assets/hands/TsenseI_hand_v3_2*/urdf/*.urdf`：项目使用的两款模型、两个手别。
- `assets/hands/TsenseI_hand_v3_2*/mjcf/*.xml`、`q_init*.yaml`：碰撞与初始姿态。
- `src/a32_kinematics/mapper.py`：模型角到机构/SDK 命令的换算。
- `src/a32_driver/a32_hardware.json`、`device.py`：毫米/度命令范围、反馈反解及最终关节范围。
- `hand_profiles.py` 和 `TopoRetargetConfig.initial_joint_values`：A3.2 重定向使用新中立姿态。
- `tools/apply_a32_joint_ranges.py`：可重复执行的资源同步；两款模型的导入脚本也调用同一 URDF 变换。

原始上传 CAD、外部 SDK 和 `src/a32_kinematics/model` 下的源机构模型保留原坐标。
源模型的零位用于机构反解，应用层负责新的坐标和限位；直接改源零位会影响直线机构求解。

## 拇指零点对齐参考 CAD（2026-10-09）

用户确认 `A3.2 URDF/urdf/A3.1V6 26.8.4-2.urdf` 中全关节为 `0` 时的拇指姿态
对应实际机械零点。本次以该文件为基准，替代 2026-09-30 的裸手网格止挡接触拟合。
源文件 SHA-256、测量方法和完整数值见 [测量结果](a32_thumb_zero_measurement.json)。

测得拇指近节（thumb MCP 的局部 +Z 纵轴）与中指 MCP 纵轴的三维夹角为 **46.893125°**。
这个值描述手指张开的几何姿态；拇指电机在此姿态下仍为 `0°`。
测量使用 URDF 正运动学，所有关节角设为 `0`，不从截图的透视投影估算角度。
网页的 MCP/PIP 初始值仍为 `0.005 rad`，与严格几何零位有轻微屈伸差异。

| 型号 | 本次根部旋转轴 origin 调整 | 本次第二旋转轴 origin 调整 | 修改前 → 修改后张角 |
| --- | --- | --- | --- |
| A3.2 裸手 | `0°` | `+14.348014°`，撤回旧的 `-0.2504200938 rad` 偏移 | `34.284160° → 46.893125°` |
| A3.2 with ID | `-5.964115°`（`-0.1040934384 rad`） | `+20.960063°`（`+0.3658221114 rad`） | `28.415415° → 46.893175°` |

两款模型的局部坐标系不同。裸手的拇指关节原点、轴向和整条拇指链恢复为参考 CAD。
with ID 保留自身连杆长度、关节平移和外壳，通过两个根部转轴匹配**相对手掌的完整拇指
MCP 朝向**，包含绕指骨自身的转角；拟合残差约 `0.000137°`。不把不同外壳的坐标值直接复制过去。
右手沿各自模型的镜像规则同步，左右手使用相同的标量零位偏移。

变换写入关节 origin：`T_new = T_source · Rot(axis, offset)`，因此页面 `q=0` 即为新零位。
`a32_thumb_zero_alignment="reference-cad-v2"` 使同步脚本和导入脚本重复执行时不会叠加偏移；
旧的 `mechanical-stop-v1` 会先撤销裸手已有偏移。URDF、MJCF、来源记录同步更新，网格与局部关键点保留。
四指 swing 模型范围仍为 `[-0.35, 0.35]`，下发仍截断到 `[-0.34, 0.34] rad`。

拇指 SDK 命令和反馈继续直接使用机械角度，保存动作的拇指数值也保持不变。
这些 origin 校正只描述模型装配姿态，不叠加到电机命令或固件零位。
本次未使能实体手，也未做硬件找零。

## 动作和日志兼容

新的动作文件写入 `_joint_coordinate_version: "a32-signed-swing-v2"`，
`_swing_axis_alignment: "id-cad-direction-v2"`。

旧正角度版本 `a32-positive-swing-v1` 在内存中按 `q_new = 0.350 - q_old` 转换四指 swing，
保留旧版模型姿态（`0 → +0.35`、`0.35 → 0`、`0.7 → -0.35`）。
该转换保留显示姿态，硬件目标则按新的有符号角和 `[-0.34, 0.34]` 限幅执行。
无版本的原始 CAD 动作使用原范围校验：带 ID 保持 swing 数值，裸手 swing 取反以匹配参考 ID 方向；
屈伸关节按当前范围限幅。下次保存才写入新版本，不批量改写已有动作文件。
当前版本不重复转换，未知版本拒绝导入。

新日志的 `metadata.joint_coordinate_version` 和 `metadata.swing_axis_alignment` 使用同一标记；
历史日志保持原始测量值。`h7.joints_ui` 保存页面值，`h7.joints_hw` 和
`conversion.joints_hw` 保存下发限幅后的关节角，例如页面 `0.35` 对应实际目标 `0.34`。

## 实时控制勾选行为

motion_play 勾选“实时关节控制”或“动作同步下位机”只发使能命令、建立起步参考，
不调用 `set_targets/send_once` 发送起步姿态，首次姿态操作前的空闲采样也不发保持帧。页面显示
“等待关节或动作指令”；调整关节、加载动作、回初始姿态或开始播放时才开始轨迹下发。
重新勾选同样等待新的操作。使能操作只记录为事件，不伪记为成功下发的姿态。

驱动增加 `enable_all(..., send_initial_pose=False)`，motion_play 使用此选项；
手势跟踪和显式找零保留各自已有的起步流程。

修改生效需要重启两套 Python 服务并刷新页面。无需重新编译 Linux 原生库。

## 2026-10-07：Python 机构参数与 MAT 参考分离

运行时 `load_configuration()` 仅读取 `src/a32_kinematics/geometry_constants.py`，不再导入 `scipy.io` 或读取 MAT；命令行的 `--config MAT` 参数已移除。源 URDF 仍提供轴向、关节顺序及角度限位。

`ORIGINAL_MOTORS` 保存原始机构数据，长度单位为米。四指 DIP 原始上限依据保留的 MATLAB 参考端点恢复：食指/无名指 12.40784398195517 mm，中指 11.194398077682767 mm，小指 12.365684120371386 mm。MAT 中也恢复这些端点，仅作为归档参考。

`DIP_STROKE_OVERRIDES_M` 单独保留当前项目的四指 DIP `[0, 0.008] m` 限制；默认运行时应用该覆盖，不改变现有有效行程、硬件配置或反馈反算。`configuration(original=True)` 只返回原始参数副本，供离线验证原始参考数据。修改参数后须重启 Python 服务以重建缓存。

2026-10-07 后续更新：按用户要求清空 `DIP_STROKE_OVERRIDES_M`，默认 Python 转换器恢复四指 DIP 原始完整行程。`a32_hardware.json` 的 8 mm 下发上限保持独立生效；驱动仍取机构与硬件范围交集。

2026-10-07 下发范围恢复：四指 DIP 硬件上限按原始机构在应用角度 1.565 rad 的输出重新计算，取消 8 mm 限制；实际下发上限略低于机构完整行程端点（源角度 1.57 rad）。
