# A3.2 关节范围与 swing 坐标更新

更新：2026-09-28。适用于 A3.2 裸手、A3.2 with ID 的左右手模型，以及手势跟踪、motion_play。

## 当前范围

| 关节 | 范围（rad） | 初始值（rad） |
| --- | --- | --- |
| 全部 PIP / DIP（包含拇指 PIP） | `[0.005, 1.565]` | `0.005` |
| 全部 MCP（包含拇指 MCP） | `[0.005, 1.3]` | `0.005` |
| 食指、中指、无名指、小指 swing（模型/页面） | `[0, 0.7]` | `0` |

拇指的两路 MIT 旋转关节保留原范围。

两款模型的四指 swing 已统一为带 ID 型号的正方向。当前模型角度下发时按以下规则处理：

```text
q_command = clamp(q_model, 0.005, 0.695)
```

原始 CAD 的轴向不同，因此从原始有正负号的角度转换时使用：

| 原始模型 | 当前模型角度 |
| --- | --- |
| SDK 裸手 | `q_model = q_original + 0.350` |
| 上传的带 ID 手 | `q_model = −q_original + 0.350` |

带 ID 仍是旧 `+0.350 → 0`、旧 `−0.350 → 0.700`。裸手改为同向后，其原始 SDK
`−0.350 → 0`、`+0.350 → 0.700`。两款原始零位都对应当前 `0.350`。
模型和页面默认值为 `0`；实际下发前才限幅到 `[0.005, 0.695]`，不做角度缩放。

## 模型姿态与 SDK 下发

带 ID 模型保留先前的变换：原轴取反，origin 右乘绕原轴 `+0.350 rad` 的旋转。
裸手四指在前一版正坐标基础上再取反轴向，origin 同时右乘绕前一版轴 `0.700 rad`
的旋转；当前裸手 `q` 与前一版裸手 `0.700−q` 的模型姿态相同，因此物理摆动范围和
`0.350` 中间姿态保持一致。相对原始 SDK，裸手最终保留原轴并将 origin 偏移 `−0.350 rad`。
在共同掌坐标系中，两款左右手四指 swing 轴向余弦均大于 `0.9999`。
网格、连杆尺寸和局部关键点继续沿用各自模型。
左右手 MJCF、执行器范围和 `q_init*.yaml` 同步更新，重定向以同一初始姿态建立掌部参考。

SDK 的四路 self swing 仍以**度**传参，正角区间为约 `[0.286479, 39.820567]°`：

- 裸手和带 ID 都直接使用限幅后的新 URDF 角度，并从 rad 换成 SDK 的 deg。
- 两款的机构计算使用 `q_model−0.350` 还原 SDK 原始 swing，原点和源轴映射同步。
- SDK 正角目标使用模型值，不额外反向。
- 两种型号的 swing 反馈都由 SDK deg 直接换算回当前模型 rad。
- self 6/7/14/15 的槽位保持不变；MIT 单位、槽位和减速比处理保持原方式。

线性关节继续使用原有非线性机构关系，硬件配置中的毫米范围由应用角度范围与机构行程范围取交集后计算。
2026-10-05 起，食指、中指、无名指、小指 DIP 的机构配置行程统一为 `[0, 8] mm`，
转换器与驱动据此收紧有效角度上限；URDF 的名义角度范围保留表中值。
例如食指 DIP 为约 `[0.039889, 8] mm`，食指 PIP 为
`[0.048521, 16.493970] mm`，食指 MCP 为 `[0.052956, 17.506244] mm`。
这些是软件模型计算出的命令范围；本次没有修改固件零位，也没有做实体行程验收。

## 修改入口

- `src/a32_kinematics/joint_coordinates.py`：范围、中立值、旧/新坐标及旧动作转换的统一定义。
- `assets/hands/TsenseI_hand_v3_2*/urdf/*.urdf`：项目使用的两款模型、两个手别。
- `assets/hands/TsenseI_hand_v3_2*/mjcf/*.xml`、`q_init*.yaml`：碰撞与初始姿态。
- `src/a32_kinematics/mapper.py`：模型角到机构/SDK 命令的换算。
- `src/a32_driver/a32_hardware.json`、`device.py`：毫米/度命令范围、反馈反解及最终关节范围。
- `hand_profiles.py` 和 `TopoRetargetConfig.initial_joint_values`：A3.2 重定向使用新中立姿态。
- `tools/apply_a32_joint_ranges.py`：可重复执行的资源同步；两款模型的导入脚本也调用同一 URDF 变换。

原始上传 CAD、外部 SDK 和 `src/a32_kinematics/model` 下的源机构模型保留原坐标。
源模型的零位用于机构反解，应用层负责新的坐标和限位；直接改源零位会影响直线机构求解。

## 裸手拇指机械零点（2026-09-30）

仅 A3.2 不带 ID 的 `left/right_hand_thumb_rotaback_joint2` 校正零位。
以 `A3.1V6 26.8.4-2.urdf` 对应网格中 rota block 的固定止挡与 rotaback 支架
首次接触为 `q=0`，关节原点沿原轴偏转 `-0.25042009379455915 rad`
（约 `-14.34801448°`）。左右手保留各自转轴和镜像关系，原点变换为
`T_new = T_CAD · Rot(axis, offset)`；平移和网格不变。
因此 `T_new · Rot(axis, q) = T_CAD · Rot(axis, q + offset)`。

左右手 URDF、MJCF 和来源记录同步更新。`a32_thumb_zero_alignment="mechanical-stop-v1"`
使导入和范围同步脚本重复执行时不会再次叠加偏移。全部关节上下限保持原值，
拇指 rotaback 仍是 `[0, 1.74] rad`，初始值仍为 `0`。带 ID 型号不采用这项校正。
这是 CAD 装配零位修正；硬件数值本来就是机械零位，SDK 命令、反馈及已存动作不叠加此偏移。
源机构模型及各连杆局部关键点保持原值，下游连杆随新的关节原点自然转动。

验证使用实际 STL 止挡接触面：零点接触，`q=+0.001 rad` 时脱离，`q=-0.001 rad`
时穿入止挡；同时检查左右镜像、URDF/MJCF 正运动学一致和电机角度不被偏移。
本次为网格几何校正，未驱动实体手；网格接触角不表示实体装配具有同等精度。

本次软件回归共 98 项通过。扩展套件另有 4 项既有失败，并用修改前的 URDF/MJCF
隔离复现：裸手及带 ID 的局部关键点并非完全镜像，两项旧测试仍要求解析求解器对象存在。
未改写这些手工关键点或求解器配置。外部 SDK 的路径断言因 WSL 中源目录位置不同未运行，
两侧模型与外部 SDK 加已记录变换后的逐属性、网格哈希比对通过。

## 动作和日志兼容

新的动作文件写入 `_joint_coordinate_version: "a32-positive-swing-v1"`。
新导出补充 `_swing_axis_alignment: "id-direction-v1"`。已有正坐标动作保留原数值和
SDK 命令目标，裸手的显示方向采用修正后的 URDF；不自动反转已保存的硬件命令。
无版本的旧文件按旧坐标校验后，在内存中将 swing 转换到 `[0, 0.7]`，并将屈伸关节限幅到新范围；
裸手使用原始 SDK 角度 `+0.350`，带 ID 使用 `−原始角度+0.350`。
下次保存才写入新版本，不批量改写已有动作文件。带版本的文件不重复转换，未知版本拒绝导入。
新日志的 `metadata.joint_coordinate_version` 使用同一标记；历史日志保持原始测量值。
`metadata.swing_axis_alignment` 记录当前轴向规则。
`h7.joints_ui` 保存页面值，`h7.joints_hw` 和 `conversion.joints_hw` 保存下发限幅后的关节角，
因此可以区分页面 `0` 和实际目标 `0.005`。

## 实时控制勾选行为

motion_play 勾选“实时关节控制”或“动作同步下位机”只发使能命令、建立起步参考，
不调用 `set_targets/send_once` 发送起步姿态，首次姿态操作前的空闲采样也不发保持帧。页面显示
“等待关节或动作指令”；调整关节、加载动作、回初始姿态或开始播放时才开始轨迹下发。
重新勾选同样等待新的操作。使能操作只记录为事件，不伪记为成功下发的姿态。

驱动增加 `enable_all(..., send_initial_pose=False)`，motion_play 使用此选项；
手势跟踪和显式找零保留各自已有的起步流程。

修改生效需要重启两套 Python 服务并刷新页面。无需重新编译 DLL，也不调用 SDK exe。

## 2026-10-07：Python 机构参数与 MAT 参考分离

运行时 `load_configuration()` 仅读取 `src/a32_kinematics/geometry_constants.py`，不再导入 `scipy.io` 或读取 MAT；命令行的 `--config MAT` 参数已移除。源 URDF 仍提供轴向、关节顺序及角度限位。

`ORIGINAL_MOTORS` 保存原始机构数据，长度单位为米。四指 DIP 原始上限依据保留的 MATLAB 参考端点恢复：食指/无名指 12.40784398195517 mm，中指 11.194398077682767 mm，小指 12.365684120371386 mm。MAT 中也恢复这些端点，仅作为归档参考。

`DIP_STROKE_OVERRIDES_M` 单独保留当前项目的四指 DIP `[0, 0.008] m` 限制；默认运行时应用该覆盖，不改变现有有效行程、硬件配置或反馈反算。`configuration(original=True)` 只返回原始参数副本，供离线验证原始参考数据。修改参数后须重启 Python 服务以重建缓存。

2026-10-07 后续更新：按用户要求清空 `DIP_STROKE_OVERRIDES_M`，默认 Python 转换器恢复四指 DIP 原始完整行程。`a32_hardware.json` 的 8 mm 下发上限保持独立生效；驱动仍取机构与硬件范围交集。
