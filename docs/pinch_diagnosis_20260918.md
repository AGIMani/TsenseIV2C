# MediaPipe 右手对指与 URDF 偏差排查（2026-09-18）

> 历史诊断记录：以下数值和代码行号对应修复前版本。2026-09-18 已完成右手映射修复，并进一步修复拇指标注点的连杆归属；当前结果见[拇指姿态问题档案](issues/20260918_thumb_retarget.md)。

## 结论

最近的碰撞开启全链路记录中，最大的可定位偏差发生在 **retarget 求解结果转右手 UI** 的边界。`retarget_runtime.py` 对右手 `thumb_swing` 额外执行 `2-q`；但左右 URDF 本身已按相同关节数值互为镜像。这会把求解得到的拇指位置移开，后续碰撞与显示使用的都是这个已改变的姿态。

这是上一轮坐标统一时保留的右手补偿规则。其历史用途是对齐实机方向，但不能同时作为当前镜像 URDF 的几何映射。仅检查 `2-q` 的往返可逆性无法发现此问题，需要检查跨手模型的指尖几何一致性。

本次只做日志分析和离线 FK / 胶囊检查，未修改运行控制代码，未连接或驱动 H7。

术语说明：模型拇指末节为 `thumb_PIP`，MediaPipe 对应 ThumbIP / ThumbTip，没有单独的拇指 DIP。若比较的是关节中心 3、7 点，本帧人手距离约 39.37 mm，当前右手模型约 95.57 mm，恢复求解器姿态后约 46.07 mm，同样存在映射放大的问题。

## 几何与碰撞复核

1. 对 18921、18928、20296 三帧，分别读取真实左右 URDF，并将左手标注点的局部坐标按 Y 镜像到右手，核对同值关节角的 21 点位置。最大镜像误差 `8.33e-17 m`。左右手只换键名即可保持镜像姿态，不需要再次翻转 thumb_swing。
2. 对代表帧现有右手 UI 姿态做静态胶囊检测：无接触，因此碰撞模块没有理由主动把拇指拉向食指。
3. 将额外翻转还原后：帧 18921 指尖标注点仍相距 25.21 mm，但 `thumb_PIP_link_cap` 与 `index_DIP_link_cap` 已有约 1.61 mm 穿入；帧 18928 为约 2.77 mm。指尖标注点不是两个指腹表面的最近点，不能把“关键点距离归零”直接当作无穿透目标。
4. 这些是当前模型的静态离线检测，不是对原会话 MuJoCo 动态状态的完整重放；取消额外翻转后的最终碰撞 / Ruckig 稳态距离尚未测定。

## 代码定位及处理顺序

- `src/utils/retarget_runtime.py:437` / `:446`：`_flip_right_thumb_swing()` 执行 `2-q`。
- `src/utils/retarget_runtime.py:534`：warm start 转回求解器时也做一次翻转。
- `src/utils/retarget_runtime.py:567`：求解器输出转右手 UI 时翻转；这是本次主要偏差入口。
- `src/protocol/hand_display_protocol.py:120`：右手显示保持数值、只改键名前缀。
- `src/app/widget.py:2290`：正常同步显示读同一条 Ruckig 的 `peek()`；日志没有每次屏幕渲染快照，表中显示阶段是按 Ruckig 样本重建，不能当作逐帧屏幕测量。
- `src/physics/mujoco_filter.py:536`：碰撞响应处理接触并限制穿透，不提供拇指到食指的主动对指目标。

建议先同步移除右手输出和 warm start 的额外数值翻转，保留输入右手关键点到左手求解器的一次空间镜像，以及输出关节键名转换。增加“求解器姿态→左右 URDF 指尖位置保持镜像”的几何回归测试，不能仅测试数值往返。

之后再复核 MediaPipe 3D 接触意图、机器人指腹接触点标定及碰撞后的间隙。当前求解使用骨向与交互图软目标，日志亦可见 `conv=False` / iteration limit；这不能单凭日志判定为主因，不应先靠放松碰撞或加大迭代掩盖映射错误。

由于右手 UI 角同值进入 H7，修正此边界也会改变实时手势的右手下发值；后续需用相同对指输入验证模型与实机运动方向。全零 init 不改变上述固定帧的 FK 结果，不是这次约 55 mm 跳变的直接来源。
