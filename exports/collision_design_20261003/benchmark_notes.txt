Offline collision projection benchmark, 2026-10-03

Scope: A3.2 normal and with-ID, LEFT side, current production MinkCollisionGuard. No hardware, retargeting, Ruckig, or UI measured. Forty deterministic synthetic targets (8 open, 8 flexion, 8 synthetic thumb-index pinch, 8 crossing fingers, 8 release), sequential state carried within each run, reset between runs. The synthetic pinch is a joint target, not a confirmed contacting grasp. Three alternating timing runs per variant (120 calls each), plus separate instrumented profile runs. WSL scheduling and concurrent tasks mean these are local observations, not real-time deadlines.

Use benchmark_final.json for the final baseline and cache-only numbers. benchmark_results.json and benchmark_variants.json are exploratory results, including a REJECTED all-bounding-spheres equivalence experiment.

Current production, median / p95 milliseconds, 120 calls:
A3.2: 0.343 / 3.501; mean 0.638; 100 geom pairs; 16 geoms, no meshes.
A3.2 with-ID: 0.778 / 19.723; mean 3.875; 90 geom pairs; 15 geoms, 5 mesh assets.
Different models return different trajectories and iteration counts; these results DO NOT isolate the cost of mesh vs capsule geometry.

Profile, with-ID (40 calls, instrumented): total 215.89 ms; 1231 feasibility evaluations; 509 path-check calls; 68804 mj_geomDistance calls; 81 QP solves. Inclusive path-feasibility time 175.53 ms (~81%), QP solve time 3.86 ms (~1.8%). Leaf distance-query time 97.42 ms (~45%). These times overlap: do NOT add path, feasibility, distance, update times. The dominant avoidable work is repeated path/distance validation, not the DAQP solve itself. Configuration.update already does mj_kinematics + mj_comPos (plus constraints only if neq>0), not full mj_forward. Installed Mink also has broadphase=True by default for QP constraints. A design should not promise gains from reimplementing either existing behavior.

Cache-only prototype: exact q byte keys for feasibility results within a project() call; exact consecutive configuration-update reuse; raw/final distance validation unchanged. All output joint values matched baseline exactly on this corpus (max absolute difference 0). A3.2 0.353 / 3.512 ms (no gain, extra overhead). With-ID 0.835 / 15.101 ms; mean 3.444 ms, ~11% mean improvement and ~23% p95 improvement in this sample, but p50 worsened and observed max worsened under noisy scheduling. With-ID profile reduced mj_geomDistance calls from 68804 to 49425 (~28%). Recommend evaluating this on real recordings before adoption, not claiming universal speedup.

REJECTED equivalence prototype: expand guard._feasible's capsule-only bounding-sphere check to all finite positive geom_rbound. With-ID output changed by 0.03 rad. In 1000 seeded random poses, three cases had sphere-pruned feasibility True while baseline full-query feasibility False. Example ring DIP mesh / pinky DIP mesh had bounding-sphere surface gap +12.177 mm but mj_geomDistance(..., distmax=0.05) returned 0 mm, below the 0.5 mm margin. This is an existing distance-query / representation numerical inconsistency that must be investigated before changing mesh pruning policy; do not silently loosen the reference acceptance logic. Exact poses and offending pairs are recorded in benchmark_variants.json.

Recommended performance plan: (1) Fit conservative low-complexity convex collision assets offline; (2) keep the existing full endpoint/path reference checker as a validation oracle while building a unified near-pair manager; (3) resolve mesh distance query inconsistency before enabling sphere/OBB pruning for mesh pairs; (4) use per-project exact repeated-pose cache only where measured useful; (5) evaluate signed clearance, path safety, output correction and end-to-end p95/p99 on identical recorded inputs for all geometry candidates. Do not disable existing raw/final checks or lower sampling density solely for speed.
