# 原生 Ubuntu 网页动作控制台

## A3.2 / A3.2 with ID

已增加两款 A3.2 的模型选择、20 关节编辑、独立动作文件、序列播放以及原生 SDK USB / ETH 控制。A3.2 的设备连接在 **Python 服务所在电脑**，Ubuntu x86_64 使用本进程 liba32_native.so，不运行 SDK `.exe`。左右手均支持硬件控制。操作流程、SDK 调用、轨迹参数和文件格式见 [A3.2 Motion Play 接入说明](../../docs/a32_motion_play.md)。下文的浏览器本机串口说明适用于 V2 / A3.0。

网页关节目标下发时，V2 的 14 路与 A3.0 的 9 路直线行程统一为 `-abs(mm)`，零行程为 `0`。UI/动作文件仍保存模型关节角（rad），旋转关节按既有符号、限位与减速比下发。该规则仅由 online 控制器启用。找零时保持原始遥测位置的命令不转换坐标。

关节控制区显示各关节的 **UI 输入范围 → USB 下发范围**，切换型号/左右手时同步更新。直线单位为 mm，旋转为 °；A3.0 外接两路显示电机端范围（包含各通道当前配置的减速比）。静态对照见 [关节范围表](joint_ranges.md)，数值为默认标定下的范围，页面使用当前 V2 行程系数计算。修改标定后可运行 `python online_control/online_motion_play/generate_joint_ranges.py` 重新生成静态表。

关节控制标题右侧的“显示”按钮可循环切换 **弧度、角度、转换后行程**。切换只改变滑块和数值输入的显示单位；动作文件、服务端会话和实际下发仍统一使用模型弧度。A3.2 的行程显示使用当前 SDK 闭环曲线，旋转输出显示为角度；没有执行器转换的关节会回退显示弧度。

当前项目唯一默认姿态为全关节 `0` 的 `init`。`thumb_swing` 的页面、模型和 H7 范围统一为 `[0,2] rad`，量程中点 `1` 不是默认姿态；历史动作文件仍可直接导入。坐标变更及文件兼容规则见 [thumb_swing 坐标说明](../docs/thumb_swing_coordinates.md)。更新已有服务器时需重新部署包含新代码和 URDF 的部署包。

浏览器提供单个 `index.html` 界面，服务器由纯 Python V2/A30/A32 会话执行动作及 Ruckig 计算；访问者浏览器通过 Web Serial 连接本机 USB。本迁移包按 Ubuntu 24.04 / Python 3.12 验证，不需要 Qt、桌面显示服务或 GPU。Three.js 已随项目提供，页面不依赖外部 CDN。

V2 / A3.0 的 H7 接到打开网页的 Ubuntu 电脑；通过桌面 Chrome/Edge 的 Web Serial 选择设备。A3.2 设备由 Python 服务所在 Ubuntu 电脑使用原生 SDK 访问。页面加载不会自动连接或使能。

## A3.0 模型与 H7 控制

在“手部型号”选择 **A3.0 · 20关节**，再选择实际左右手。A3.0 使用独立 URDF/STL、机构限位、动作文件和 H7 协议；原 V2 的 21 关节与功能保留。切换型号或手别前必须断开下位机，旧页面的关节操作标识随后失效，避免跨型号下发。

1. 将 **A3.0 固件的 H7** 接到打开网页的电脑，授权本机串口后连接。连接本身不使能、不发送姿态，等待页面显示“遥测正常”（不要求全部电机在线）。串口参数为 115200 / 8N1，无流控。
2. 分别填写已实机标定的“直线找零 Iq”和“旋转找零 Iq”，单位为协议电流码值，不是安培；默认0不允许找零。点击“18路一键找零”并确认，按电机顺序执行复位回零态 → 等待新反馈确认 → 使能 → 寻零 → 等待完成/错误。复位确认超时1.5秒，寻零超时15秒；结果显示在“找零结果”。
3. “复位回零态”向18路自研电机发送 `0x22 / cmd=2`，并停止实时/序列下发。它不移动关节、不重启H7。“回到初始姿态”将关节目标设为初始姿态，开启实时控制时通过 Ruckig 平滑移动；未开启时只预览。
4. 可直接勾选“实时关节控制”，无需先找零，也不要求全部18+2路在线。在线且有效的通道从实际反馈反解起步，缺失反馈的通道使用页面当前姿态，再发送保持帧并使能自研电机；页面显示缺失反馈数量。这些备用值是指令目标，不是设备实测位置。然后调整滑块或弧度输入；开启过程中不会自动找零。
5. 编排动作时可保存、加载、删除、导入、导出并循环播放。选择“动作同步下位机”后可同步播放；该模式与实时关节控制互斥。A3.0 动作文件带 `_model_id`、`_hand_side` 和 `motions`，与 V2 及另一手别文件互不混用。
6. 顶部“停止下发”在本机停止位置帧、取消找零、请求自研电机断电并断开串口，需要手动重连；“停止 / 自研断电”还向18路自研电机请求断电。**两路外接拇指电机没有独立找零、复位和断电指令**，仅能停发位置，找零结果会明确列出这两路未支持，不能套用 V2 指令。

转换链为：20关节弧度 → 9路直线行程(mm) + 11路旋转角度(deg) → 108字节 A3.0 `0x20` 帧。复用工作区 A3.0/A3.2 机构转换代码及已确认槽位；外接位置和速度按各通道当前配置的减速比换算一次，CRC16-Modbus覆盖完整帧头与载荷。

实时控制启动时，全部20关节（9路直线、9路自研旋转、2路外接旋转）的有限反馈若超出机构/模型范围，均采用最近的边界作为起步目标，不再因行程或角度越界拒绝启动。页面显示反馈值与采用值，原始遥测不修改。直线反馈先按协议符号还原为机构行程，再夹紧并反解；外接反馈先换算到输出轴。启动首帧使用修正后的目标，因此越界轴可能向边界位置移动。这是启动兼容处理，不是零位或机构标定修正。目标关节限位、新鲜遥测、有限数值及电机故障检查仍保留，无需先找零。

A3.0 动作播放使用独立收发线程，Ruckig采样与位置帧生产目标均为1000 Hz（1 ms），共享手势项目仍为500 Hz；各型号、左右手和关节类型的 Ruckig 默认上限统一为速度20 rad/s、加速度400 rad/s²、jerk 2400 rad/s³，见[共用运动参数](../../docs/motion_limits.md)。计时使用 `perf_counter`，按绝对时刻调度，迟到只发最新位置，不突发补发历史帧。浏览器收发和网络解析移入 Dedicated Worker，页面仅保留授权和界面；目标浏览器须支持 Worker Web Serial。实际速率受操作系统、网络和USB设备限制。

浏览器与服务端协商二进制连续下发流，使用HTTP长连接和TCP_NODELAY，免去高频JSON/Base64编码。Worker 内的网络读取与串口写入分离，复用缓冲区，相邻积压位置仅保留最新记录，仍保留使能/找零命令顺序。位置帧逐包写入，最小调度间隔约1.2 ms；基于上一成功写出位置检查关节跳步，超限或积压时停止并断开。A3.0轨迹元数据只用于网络传输和连续性检查，剥离后H7仍接收108字节位置帧。需配套重启服务并刷新页面，旧服务没有连续性元数据时不具备该保护。

本地模拟USB验收中，Worker正常/高UI负载的间隔中位数为1.5/1.4 ms，1–4 ms占比99.89%/99.95%，仍有11.6/10.8 ms长尾，**尚未满足每包都在1–4 ms**。没有以模拟结果替代真实H7测试。完整结果、保护边界和复现方式见 [Worker本地测试记录](../../docs/a30_browser_worker_test.md)。

页面显示最近约1秒的实际位置帧写出Hz、接收KiB/s、交换Hz和最新交换耗时（包含服务端等待）。位置Hz不计使能/找零帧，表示浏览器写入完成频率，不是H7执行确认。串口仍为115200/8N1，无流控；H7原生USB CDC的实际带宽由USB/固件决定，不通过盲目提高波特率改变设备配置。

循环停顿超过100 ms、遥测整帧超过500 ms、在线通道无效数值或在线外接电机故障时停发；网络往返超过150 ms、命令总年龄超过200 ms或串口链路超过350 ms时停止并断开，不自动重连。连续位置样本只保留最新帧，控制命令保持顺序。切到后台、释放控制和断开串口会在本机取消找零并请求断电。浏览器/操作系统崩溃或USB断开时无法保证最后的停止指令送达。控制权另有5秒租约，不替代串口链路超时。

本机模拟基准与复现命令见 [串口收发性能记录](../docs/online_motion_serial_performance.md)。基准不连接实体电机，不代表node0网络与真实USB的保证速率。

本页提供关节/机构限位及 Ruckig 平滑手动控制，**未接入视觉页面的碰撞检测/Mink避碰**。9路连杆几何沿用现有 A3.2 参数，电流、零位、运动方向及机构参数仍需实机验证。协议中的复位/断电是请求，位置停发不等同硬件急停。

A3.0 左右手动作分别保存为数据目录下的 `motions_a30_left.json`、`motions_a30_right.json`。重新执行部署脚本保留这些文件；备份时请备份整个数据目录。最新部署包已包含 A3.0 网格、profile、机构 `.mat`/URDF 及 SciPy/PyYAML 依赖，不需要另外复制模型。

遥测与 `A3_USB_Downlink.pyw` 使用相同 AA55 / DEV=3 / FUN=0x02 / CRC16-Modbus 帧：载荷444–483字节时截取前444字节（18路自研），载荷484–2040字节时截取前484字节（18+2）；完整线帧上限2048字节，与参考程序一致。接收完整帧并校验包括扩展字节在内的CRC后，才截取已知字段，剩余扩展字段跳过。头部 `<HHII>`，自研槽24字节、外接槽20字节。电机位置、在线掩码、找零状态和外接50倍换算一致。网页仅展示控制所需的遥测摘要，不完整复制参考程序的板温、电压及逐电机诊断表。实时控制仍需500 ms内的新鲜电机遥测帧，找零期间保持互斥；主动执行整手找零仍需完整反馈以逐轴确认结果。

## 本机安装与启动

按项目根目录 README-UBUNTU.txt 安装系统依赖，然后在根目录执行：

    bash migration/ubuntu/install.sh play
    bash migration/ubuntu/start-play.sh

打开 http://127.0.0.1:8765/ 。动作文件写入 runtime/ubuntu/play。
需要原生 A3.2 设备时使用此本机入口。

可选的通用 deploy.sh 是面向浏览器串口的 systemd 服务部署入口，会修改系统账户和服务，且通过 PrivateDevices 隔离服务端设备。它不用于本次 A3.2 本机 USB 启动，也未在新机实际注册验证。
独立网页服务包仍可用 package.py 生成；本迁移包直接保留完整工程，无需先生成独立包。

## 访问页面

本机使用 localhost/127.0.0.1；跨电脑访问并使用浏览器串口时，需按下方配置受信任的 HTTPS 入口。网页直接打开，无需输入密码。

无需登录，也没有密码会话有效期。第一个打开的页面自动获取控制权，其他页面只读查看。控制者点击“释放控制”后，其他页面可点击“获取控制”。关闭/刷新控制页或失联后，最多 5 秒释放控制权；只读页面和健康检查不会延长原控制者的控制权。

修改端口、增加内网域名，或为已启用的 UFW 增加限定网段规则：

```bash
sudo bash online-motion-play/deploy.sh --port 8765 --allowed-host hand.example.lan --allow-cidr 192.168.1.0/24
```

`--allow-cidr` 仅在 UFW 已启用时添加指定网段到服务端口的规则，不关闭防火墙。云服务器安全组也需允许相同内网网段访问该端口。服务器 IP 改变后，可重新运行脚本更新允许地址，或使用固定内网 IP/域名。

## 更新、日志和数据

本机迁移入口的数据目录是 runtime/ubuntu/play；以下 /opt、/var/lib 路径仅适用于可选 deploy.sh 系统服务。

更新仓库或换成新部署包后，再执行同一部署命令即可。已有配置和工作动作保留，旧网页密码配置会自动移除。新版本通过预检查才会切换；启动或健康检查失败时恢复之前的代码链接及配置。历史版本保留在 `releases/` 中。

| 内容 | 服务器路径 |
| --- | --- |
| 当前程序与 Python 环境 | `/opt/online-motion-play/current/` |
| 历史版本 | `/opt/online-motion-play/releases/` |
| 配置 | `/etc/online-motion-play/config.json` |
| 动作工作副本 | `/var/lib/online-motion-play/motions.json` |
| 服务日志 / 下发 HEX | systemd journal |

```bash
sudo systemctl status online-motion-play
sudo journalctl -u online-motion-play -f
sudo systemctl restart online-motion-play
sudo systemctl stop online-motion-play
```

备份动作文件和配置目录即可保留动作及访问设置。导入会替换工作副本，保存/删除动作会更新工作副本；原始导入文件不被修改，页面可以导出 JSON。

本机和远程服务均已移除网页访问密码；升级时清理 `password_hash` 和 `access-password.txt`，旧配置也不会恢复密码校验。

## 网络和 HTTPS

浏览器本机串口要求受信任的 HTTPS；仅开发时的 `http://localhost` / `http://127.0.0.1` 例外。内网 IP 的 HTTP 地址可以查看页面但不能连接本机串口。跨电脑部署需配置新机自己的证书或反向代理。后端检查明确列出的 Host/Origin，不使用通配允许；页面与API不要求密码；仍保留同源检查、控制权独占及浏览器串口授权。

可以向原配置合并以下字段，使用受浏览器信任的证书直接提供 HTTPS：

```json
{
  "tls_cert": "/etc/online-motion-play/tls/fullchain.pem",
  "tls_key": "/etc/online-motion-play/tls/privkey.pem"
}
```

保留原有配置字段，允许服务账户读取证书/私钥，然后重启服务。私钥无需对其他用户开放。也可以使用现有反向代理：将后端 `host` 改为 `127.0.0.1`，配置 `public_origin` 为实际的 `https://hand.example.lan`（多个入口可用 `public_origins` 数组），代理保留原始 Host，并转发所有页面、API 和模型路径。HTTPS 入口用于浏览器本机串口访问，不再使用登录 Cookie。

## V2 Form2 功能

| 功能 | 网页实现 |
| --- | --- |
| 左右手模型 | 原始 URDF/STL；旋转、平移、缩放、重置视角 |
| 21 个关节 | 原有限位、滑块与弧度输入，回车/失焦提交 |
| 动作管理 | 保存、覆盖、删除、加载、过渡/间隔时间 |
| 动作文件 | `.txt`/`.json`、UTF-8 BOM、旧版数组、左右手角度转换、导出 |
| 序列播放 | 从选中动作开始、循环、停止、短序列最终姿态刷新 |
| 下位机 | 服务器实体串口连接/断开、实时关节控制、动作同步、HEX 日志 |
| 电机操作 | 五指往返、直线回零/复位、旋转校准、整手一键找零与确认框 |

500 Hz Ruckig、协议转换、DownlinkGuard 和找零状态机在服务器执行，网络传输界面操作与显示状态。实际发送频率仍受服务器负载与操作系统调度影响。纯 Python 事件循环处理网页控制，独立线程执行运动采样，网页承担可见界面与 3D 渲染；不再导入或启动 Qt。

动作序列保留原版整条轨迹的累计时间轴：密集关键帧不会逐段重新计时或
逐段阻塞 flush；线程迟到时采样当前目标，不突发补发过期帧。`interval=0`
表示不额外停留，微小正停留也保留累计时长。原有 Ruckig/DownlinkGuard 和
序列结束后的终态收敛保持不变，因此结束时间仍可能包含收敛耗时。

服务端直接保存当前动作与姿态快照；/api/state 的 playback_timing 保留文件时长、轨迹时间、迟到采样数、终态收敛与总耗时。停止任务会隔离旧线程的后续帧，关闭服务会释放控制会话。
更新已有部署时需重新打包/部署，只刷新浏览器页面不会替换服务器中的共享 Python 代码。

浏览器实时关节下发沿用 Form2 的“目标 → 服务端 Ruckig → 协议转换 → 本机 USB”流程。
取消了浏览器额外的“相邻位置差超过最大速度 × 4 ms 就断开串口”检查，以及按该
位移差追加的等待；网络合并中间样本不会因此要求重连。服务端运动限值、非有限值、
CRC、会话和超时检查继续生效。位置包逐包发送，目标间隔 2 ms，不突发补发积压包。
Worker 状态的 `metrics.position_write_intervals` 给出实际成功写入的调用起始间隔
（p50/p95/p99、最大值及 1–3 ms 占比）；这是浏览器端测量，不能当作 H7 收包时间。

“停止下发”、释放控制权或失联处理会停止软件任务并按需断开串口，不等价于硬件急停，也不能撤销已发给固件的寻零命令。服务不会自动连接或自动驱动设备。
